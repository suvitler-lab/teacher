# งานครบ — ระบบสแกนส่งงานและเช็คชื่อออนไลน์

เว็บแอป (ติดตั้งลงมือถือได้แบบ PWA) สำหรับคุณครู ใช้สแกน QR ประจำตัวนักเรียนเพื่อรับงานและให้คะแนน
เช็คชื่อ สุ่มชื่อ และสรุปผลออกเป็น Excel ทำงานบน **Cloudflare Workers + D1** อยู่บน **Free tier ค่าใช้จ่าย 0 บาท**

## ความสามารถ
- **สแกนส่งงาน** — กล้องมือถือหรือเครื่องยิง QR (USB/Bluetooth) เข้ากระบวนการเดียวกัน
  - 3 โหมด: ให้คะแนนเต็มทันที · กรอกคะแนนทันที · รับงานก่อนค่อยให้คะแนน
  - กันสแกนซ้ำ แจ้งผล+เสียงทันที ใช้ต่อได้แม้เน็ตหลุด (บันทึกคิวไว้แล้วส่งเมื่อกลับมาออนไลน์)
  - อ่านตำแหน่งปุ่มจริง (KeyboardEvent.code) จึงอ่านรหัสถูกแม้แป้นพิมพ์เป็นภาษาไทย
- **สมุดคะแนน** — ตาราง นักเรียน × งาน, ปุ่มทั้งห้องส่งแล้ว/ให้เต็ม/ล้าง, กรอกในตาราง Enter ลงคนถัดไป
- **จัดการงาน** — ประเภทงาน (แบบฝึกหัด/ใบงาน/กิจกรรม/ชิ้นงาน/การบ้าน/สอบ), คะแนนเต็ม, กำหนดส่ง, หลายห้อง
- **เช็คชื่อ** — แตะเลือก มา→สาย→ลา→ป่วย→ขาด หรือสแกน (หลังเวลาที่ตั้ง = สาย), รายวันหรือรายคาบ
- **สุ่มชื่อ** — สุ่มเฉพาะคนที่มา (ถ้ายังไม่เช็คชื่อ/ไม่มีใครมา จะบอกเหตุผลและให้เลือกใช้ทั้งห้องเอง) ไม่ซ้ำจนครบห้อง จับกลุ่ม โหมดจอใหญ่ (กด Space)
- **นักเรียน** — นำเข้าจาก Excel (ตรวจก่อนนำเข้า: เพิ่ม/แก้/ย้ายห้อง/กลับมาใช้งาน กี่คน), ออก QR ใหม่รายคน/ทั้งห้อง, พิมพ์สติกเกอร์ QR (10/21/40 ดวงต่อ A4)
- **รายงาน** — สรุปรายเดือน/ภาพรวมห้อง, กราฟอัตราส่ง, รายชื่อค้างส่ง, คัดลอกไป LINE, ส่งออก Excel 4 ชีต
- **ปีการศึกษา/ภาคเรียน** — ห้องเรียนเป็นของแต่ละปีการศึกษา ขึ้นปีใหม่แล้วได้ห้องว่างชื่อเดิม ข้อมูลปีเก่าเก็บครบและดู/แก้คะแนนย้อนหลังได้จากตัวเลือกเทอม (ดู "สิ้นภาคเรียนและสิ้นปีการศึกษา")
- **ใช้ออฟไลน์** — เปิดแอปครั้งแรกตอนมีเน็ตแล้ว แอปจะเก็บไฟล์ของตัวเองไว้ในเครื่อง (ราว 3 MB) ต่อมาเปิดและสแกนได้แม้ไม่มีอินเทอร์เน็ต งานที่สแกนเข้าคิวในเครื่องแล้วส่งเองเมื่อกลับมาออนไลน์ ดูสถานะที่ ตั้งค่า → ทั่วไป → "ใช้ออฟไลน์" เวอร์ชันใหม่จะแจ้งเป็นแถบให้กดเอง ไม่เปลี่ยนกลางคัน
- **ตั้งค่าพื้นฐาน** — เพิ่ม/แก้ชื่อ/เรียงลำดับ ห้องเรียน วิชา ประเภทงาน (สี, คะแนนเต็มเริ่มต้น) และเก็บรายการที่เลิกใช้โดยข้อมูลเดิมไม่หาย
- **ความปลอดภัย/ตรวจสอบ** — ประวัติการแก้ไข (ใครแก้อะไร เมื่อไหร่ จากเครื่องไหน), สำรอง/กู้คืนข้อมูล
- **หน้าผู้ปกครอง** — เปิด/ปิดในตั้งค่า (ค่าเริ่มต้นปิด · จะพัฒนาต่อในเฟสถัดไป)

## เทคโนโลยี
- Worker: Hono + Zod · ฐานข้อมูล D1 (SQLite) · หน้าเว็บ: Vite + Preact + TypeScript (PWA)
- สแกน: BarcodeDetector ของเครื่อง หรือ zxing-wasm (โฮสต์ไฟล์เองเพื่อใช้ออฟไลน์)
- ทดสอบ: Vitest + `@cloudflare/vitest-pool-workers`

## รันในเครื่อง (สำหรับพัฒนา)
```bash
npm install
npm run db:migrate:local      # สร้างตารางใน D1 local
npm run db:seed:local         # ใส่ข้อมูลตัวอย่าง (ชื่อสมมติ)
npm run dev                   # เปิด http://localhost:5173
```
ตั้งค่าลับสำหรับ dev ในไฟล์ `.dev.vars` (คัดลอกจาก `.dev.vars.example`): `SETUP_CODE`, `SESSION_PEPPER` — ไม่มีค่าเริ่มต้น ถ้าไม่ตั้ง ระบบจะปฏิเสธการตั้ง/เข้าสู่ระบบและบอกสาเหตุ
เปิดครั้งแรกไปที่ `/` แล้วตั้งรหัสผ่านครูด้วย `SETUP_CODE`

คำสั่งอื่น: `npm run typecheck` · `npm test` · `npm run build` · `npm run e2e:offline` (ออฟไลน์) · `npm run e2e:camera` (กล้อง/เครื่องยิง) ·
`npm run e2e:rehearsal` (ซ้อมวันทดลอง) ในเบราว์เซอร์จริง ดู `docs/OPERATIONS.md` §8 · ทดลองในห้องเรียนจริง 1 ห้อง: [`docs/TRIAL.md`](docs/TRIAL.md)
(เทียบกระดาษกับแอปด้วย `npm run trial:reconcile`)

## นำขึ้นใช้งานจริงบน Cloudflare (0 บาท)
> ทำครั้งเดียว ครูต้องมีบัญชี Cloudflare (สมัครฟรี ไม่ต้องผูกบัตร)

1. เข้าสู่ระบบ Cloudflare (จะเปิดเบราว์เซอร์ให้กดอนุญาต):
   ```bash
   npx wrangler login
   ```
2. สร้างฐานข้อมูล แล้วนำ `database_id` ที่ได้ไปใส่แทนค่าใน `wrangler.jsonc`:
   ```bash
   npx wrangler d1 create kru-db
   ```
3. สร้างตารางบนฐานข้อมูลจริง:
   ```bash
   npm run db:migrate:remote
   ```
   > **ทุกครั้งที่อัปเดตโค้ดที่มีไฟล์ใหม่ใน `migrations/` ให้รันคำสั่งนี้ก่อน `npm run deploy` เสมอ**
   > (ตอนนี้ schema เป็น v5 — มี migration `0005` และ `0006` ที่ต้องรันก่อน deploy) — ถ้ายังไม่ได้ migrate ระบบจะตอบ `schema_mismatch` และไม่ยอมทำงานจนกว่าจะ migrate
4. ตั้งค่าลับ (พิมพ์ค่าเมื่อระบบถาม — ตั้งให้เดายาก):
   ```bash
   npx wrangler secret put SETUP_CODE
   npx wrangler secret put SESSION_PEPPER
   ```
5. Deploy:
   ```bash
   npm run deploy
   ```
   คำสั่งนี้ตรวจให้ก่อนและหลัง build (`database_id` ยังเป็นตัวอย่างไหม, migration ครบและตรงกับแอปไหม, ไฟล์ออฟไลน์ถูกสร้างไหม) และหยุดพร้อมบอกสิ่งที่ต้องแก้
6. เปิดลิงก์ `https://<ชื่อ>.<subdomain>.workers.dev/` แล้วตั้งรหัสผ่านครูด้วย `SETUP_CODE`
7. ตรวจว่าระบบพร้อม: `npm run check:health -- https://<ชื่อ>.<subdomain>.workers.dev` ต้องขึ้น ✔
   (บอกเป็นภาษาคนถ้าฐานข้อมูลว่าง, schema ไม่ตรง หรือยังไม่ตั้ง `SESSION_PEPPER`)

การ deploy ซ้ำ ย้อนรุ่น ลืมรหัสผ่าน ซ้อมกู้คืน และแก้อาการต่าง ๆ: ดู [`docs/OPERATIONS.md`](docs/OPERATIONS.md)

> **อย่าอัปเกรดเป็น Workers Paid** เพื่อให้ค่าใช้จ่ายเป็น 0 บาท หากใช้เกินโควตาฟรี ระบบจะแจ้งเตือน
> ไม่เก็บเงิน
>
> **ใช้โควตาแค่ไหน (วัดจากชุดข้อมูลขนาดโรงเรียนจริง: 200 นักเรียน · 40 งาน · คะแนน 8,000 รายการ · เช็คชื่อ 12,000 รายการ):**
> วันสอนปกติ (สแกน 200 ครั้ง, เช็คชื่อ 5 ห้อง, เปิดหน้าแรก/สแกนราว 30 ครั้ง, ดูสมุดคะแนน/รายงาน 20 ครั้ง) อ่านราว 0.65 ล้านแถว (~13% ของโควตาอ่านรายวัน)
> และเขียนราว 4,000 แถว (~4% ของโควตาเขียน) — สแกนหนึ่งคนอ่าน ~50 แถว เขียน ~9 แถว
> **ข้อควรระวัง:** การ**กู้คืนข้อมูลเต็มชุดที่ขนาดนี้เขียนราว 92,000 แถว** เกือบเท่าโควตาเขียนทั้งวัน (~100,000) —
> ทำนอกเวลาเรียน ไม่ทำซ้ำในวันเดียวกัน (ถ้าโควตาหมด ระบบเขียนไม่ได้จนถึงเที่ยงคืน UTC; การกู้คืนที่ล้มจะย้อนกลับ ข้อมูลเดิมไม่เสีย)
> ตัวเลขเหล่านี้มี test คุมงบไว้ (`test/api/volume.test.ts`) — โควตาของ Cloudflare เปลี่ยนได้ ตรวจที่ dashboard

## สิ้นภาคเรียนและสิ้นปีการศึกษา
ครูไม่ต้องเลื่อนชั้นหรือจับคู่ห้อง (เด็กที่ขึ้นชั้นไปแล้วไม่ได้เรียนกับครูต่อ) — ห้องเรียนแต่ละห้อง**เป็นของปีการศึกษาหนึ่งปี**

1. **สลับเทอมในปีเดียวกัน (1/2569 → 2/2569):** ตั้งค่า → ข้อมูลพื้นฐาน → ภาคเรียน → **เริ่มภาคเรียนใหม่** (หรือกดจากแถบเตือนบนหน้าหลักเมื่อเลยวันสิ้นสุดเทอม)
   ใส่วันเริ่ม แล้วกดเริ่ม — ห้องและนักเรียนเหมือนเดิม เปลี่ยนเฉพาะเทอมปัจจุบัน
2. **ขึ้นปีการศึกษาใหม่ (2/2569 → 1/2570):** ใช้ปุ่มเดียวกัน หน้าต่างจะสรุปให้ก่อนกดยืนยัน
   - ติ๊กห้องที่เปิดต่อ → ได้ห้องใหม่**ชื่อเดิม ปีใหม่ ว่างเปล่า**
   - ห้องปี 2569 ถูกเก็บพร้อมนักเรียน (สถานะ "จบปีการศึกษา") งาน คะแนน และเช็คชื่อทั้งหมด — **ไม่ถูกแก้หรือลบ**
   - เลือกได้ว่าจะปิดรับงานที่ยังเปิดของปีเก่าไหม
3. **นำเข้านักเรียนใหม่** เข้าห้องใหม่ของปีนี้ที่หน้านักเรียน (ถ้านำเข้าเด็กชุดใหม่ไปห้องเดิมของปีก่อน ระบบจะเตือน)
4. **ดูย้อนหลัง:** เลือกเทอมของปีก่อนที่ตัวเลือกเทอมมุมขวาบน — สมุดคะแนน/รายงาน/Excel/นักเรียน แสดงห้องและเด็กของปีนั้น
   ตัวเลขเท่าเดิมทุกตัวไม่ว่าจะนำเข้าเด็กใหม่ไปกี่คน ยังตรวจและแก้คะแนนงานปีเก่าได้ ส่วนสแกน/เช็คชื่อ/สุ่มชื่อใช้ห้องของปีปัจจุบันเท่านั้น
5. เด็กย้ายออก/ไม่ใช้งานกลางเทอม: เลือกสถานะที่หน้าแก้ไขนักเรียน ระบบบันทึก "วันที่ออก" ให้ (แก้ได้) — เด็กคนนั้นยังอยู่ในรายงานเทอมก่อนหน้า แต่ไม่อยู่ในเทอมที่ออก
   > ข้อจำกัด: ถ้าเด็กซ้ำชั้นและครูสอนต่อ แล้วนำเข้าเด็กคนเดิมเข้าห้องใหม่ ประวัติปีเก่าของคนนั้นจะไม่แสดงในรายงานปีเก่า (ระบบเตือนตอนนำเข้า)

## สำรองและกู้คืนข้อมูล
- **สำรอง:** ตั้งค่า → สำรองข้อมูล → ดาวน์โหลด (ได้ไฟล์ `.json`) ควรทำเป็นประจำ
  - ระหว่างอ่านข้อมูล ถ้ามีเครื่องอื่นบันทึกอยู่ ระบบจะอ่านใหม่เอง (สูงสุด 3 รอบ) และถ้ายังไม่นิ่งจะ **ไม่สร้างไฟล์** เพื่อไม่ให้ได้ไฟล์ที่ครึ่งก่อนครึ่งหลัง — หยุดสแกน/เช็คชื่อสักครู่แล้วลองใหม่
  - ไฟล์มีข้อมูลนักเรียนและ QR/PIN: เก็บในที่ปลอดภัย ดู `docs/OPERATIONS.md`
- **กู้คืน:** ตั้งค่า → กู้คืน → เลือกไฟล์ → พิมพ์ "ยืนยัน"
  - **กู้คืนแทนข้อมูลปัจจุบัน:** ข้อมูลที่เกิดหลังวันที่สำรองจะหายไป (ไม่ใช่การรวมข้อมูล) ระบบดาวน์โหลดสำรองข้อมูลปัจจุบันให้อัตโนมัติก่อนเริ่ม
  - ส่งข้อมูลขึ้นไปพักไว้ก่อน แล้วสลับเข้าไปทีเดียวในธุรกรรมเดียว — **ถ้าล้มเหลวหรือปิดหน้าต่างกลางคัน ข้อมูลเดิมไม่ถูกแตะเลย**
  - รหัสผ่านครูและเครื่องที่เข้าระบบไว้ไม่อยู่ในไฟล์สำรอง จึงไม่ถูกเปลี่ยน (กู้คืนไปเครื่องใหม่แล้วยังใช้รหัสผ่านของเครื่องนั้น)
  - **คำขอที่กำลังเดินทางอยู่ระหว่างกู้คืนจะไม่เขียนทับข้อมูลที่เพิ่งกู้คืน** — ฐานข้อมูลตรวจซ้ำในขั้นเขียนจริงว่าข้อมูลยังเป็นชุดเดิมที่คำขอนั้นเห็น ถ้าไม่ใช่จะปฏิเสธ (รายการจะไปรอที่ "ต้องตรวจสอบ")
  - ถ้าค้างงานกู้คืนไว้ ดูและยกเลิกได้ที่ ตั้งค่า → สำรองข้อมูล
  - **ถ้าเน็ตหลุดตอนกำลังเปลี่ยนข้อมูล** หน้าต่างจะถามเซิร์ฟเวอร์ว่างานของตัวเองสำเร็จหรือยัง และจะไม่บอกว่า "ไม่มีอะไรเปลี่ยน" ถ้ายังไม่รู้ผล (มีปุ่ม "ตรวจสอบผล")
  - **กู้คืนแล้วรายการค้างของทุกเครื่องถูกพักไว้:** คะแนนที่ยังรอส่งและเช็คชื่อที่แตะไว้ก่อนกู้คืน ไม่ถูกส่งเข้าข้อมูลชุดใหม่เอง — จะขึ้นในรายการ "ส่งไม่สำเร็จ" / "ต้องตรวจสอบ" ให้ครูเลือกส่งใหม่หรือทิ้ง
    เครื่องอื่นที่ยังไม่รู้ว่ามีการกู้คืนจะขึ้นแถบให้โหลดข้อมูลใหม่ก่อนทำต่อ
- ตาข่ายสุดท้าย: D1 Time Travel ย้อนข้อมูลได้ 7 วัน (`npx wrangler d1 time-travel restore kru-db`) — ใช้เมื่อเกิดเหตุที่ไฟล์สำรองช่วยไม่ได้

## เก็บข้อมูลในเครื่อง (สำคัญสำหรับ iPad/iPhone)
คะแนนที่ยังไม่ได้ส่งและร่างเช็คชื่อ เก็บไว้ในเครื่องจนกว่าจะส่งขึ้นระบบสำเร็จ Safari อาจลบข้อมูลของเว็บที่ไม่ได้เปิดนานราว 7 วัน
(เช่นช่วงปิดเทอม) จึงควร **เพิ่มแอปไว้ที่หน้าจอโฮม** (แชร์ → เพิ่มลงในหน้าจอโฮม) — ดูสถานะได้ที่ ตั้งค่า → ทั่วไป → ที่เก็บข้อมูลในเครื่องนี้

## หมายเหตุเรื่องกล้อง
กล้องต้องเปิดผ่าน HTTPS (workers.dev เป็น HTTPS อยู่แล้ว) และให้ทดสอบบนมือถือจริงทั้ง Android และ iOS
