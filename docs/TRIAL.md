# ทดลองใช้ในห้องเรียนจริง 1 ห้อง (รอบ 4)

เป้าหมาย: ใช้ระบบตลอดวันสอนหนึ่งวันกับห้องเดียว **คู่กับบันทึกกระดาษ** แล้วดูว่าผลตรงกันทุกรายการไหม และครูต้องกดซ้ำหรือไม่เข้าใจตรงไหน
"เมื่อผลตรงกันจึงขยายไปทุกห้อง" — ถ้าไม่ตรง ยังไม่ขยาย

> **สิ่งที่การทดลองนี้ต้องการและทำแทนกันไม่ได้:** มือถือ/แท็บเล็ต/เครื่องยิง/เครื่องพิมพ์ **เครื่องจริงที่จะใช้จริง**, แสงและระยะในห้องเรียน, wifi ของโรงเรียน,
> และเด็กจริงที่ถือบัตร ผมทดสอบทุกอย่างที่ทดสอบได้โดยไม่มีสิ่งเหล่านี้แล้ว (ดูหัวข้อ 0) แต่ **ไม่ได้ทดลองในห้องเรียนเอง**

## 0. ตรวจไปแล้วโดยไม่ต้องมีอุปกรณ์ / ต้องทดลองเท่านั้น

| ตรวจแล้ว (Chromium, เซิร์ฟเวอร์ทดสอบ, ข้อมูลสมมติ) | ยังไม่ได้ตรวจ — การทดลองนี้ต้องตอบ |
|---|---|
| กล้องอ่าน QR จริงจากวิดีโอได้ผ่านตัวอ่านสำรอง (WASM) ภายใต้ CSP จริง, ถือบัตรค้างไว้ไม่บันทึกซ้ำ, QR เล็ก/เอียงอ่านได้ในภาพสังเคราะห์ที่คมชัด (`npm run e2e:camera`) | กล้อง**เครื่องจริง**: แสง โฟกัส ระยะ บัตรพิมพ์/เคลือบสะท้อนแสง QR ดวงเล็ก (สติกเกอร์ 40 ดวง/แผ่น) |
| เครื่องยิงแบบ keyboard บนแป้นภาษาไทยส่งรหัสถูก (จำลองการกดปุ่ม) | เครื่องยิง**รุ่นที่ใช้จริง**: ส่ง Enter ท้ายรหัสไหม, ความเร็วกดปุ่ม, Bluetooth หลุด |
| ออฟไลน์ครบวงจร: เปิดครั้งแรก → ตัดเน็ต → reload → สแกนเข้าคิว → ออนไลน์แล้วส่ง, session หมดอายุ, ปิดแอปเปิดใหม่, เวอร์ชันใหม่, เน็ตค้าง (`npm run e2e:offline`) | **Safari บน iPad/iPhone** (service worker และการล้างข้อมูลเว็บของ Safari), wifi โรงเรียนที่ตัด/ค้างจริง |
| ซ้อมทั้งวงจรของวันนี้: เช็คชื่อ + สแกน → ไฟล์สำรองจากปุ่มจริง → เทียบกับกระดาษ (`npm run e2e:rehearsal`) | ครูจดกระดาษ**จริง**ระหว่างสอนพร้อมกับใช้แอป — ความผิดพลาดของคนเป็นอีกเรื่อง |
| ข้อมูลขนาดโรงเรียน 200 คนอยู่ในโควตาฟรี (README, `docs/OPERATIONS.md` §7) | โควตา**จริง**ของบัญชี Cloudflare ของโรงเรียนในสัปดาห์แรก |
| หน้า "ตรวจเครื่องนี้" (ตั้งค่า → อุปกรณ์และรหัสผ่าน) | ผลของมันบนเครื่องแต่ละเครื่องของจริง |
| งานพิมพ์: ยังไม่ได้ตรวจ | สติกเกอร์ QR จากเครื่องพิมพ์จริง อ่านได้ทุกดวงไหม |

## 1. ก่อนวันทดลอง (ทำให้เสร็จอย่างน้อย 1 วันก่อน)

**ระบบ**
- [ ] `docs/OPERATIONS.md` §1 ครบ: สร้างฐานข้อมูลจริง, ตั้ง `SESSION_PEPPER`/`SETUP_CODE`, `npm run deploy` ผ่าน, `npm run check:health -- <ลิงก์>` ขึ้น ✔
- [ ] ตั้งปีการศึกษา/ภาคเรียนพร้อมวันเริ่ม–สิ้นสุด, ห้อง, วิชา, นำเข้านักเรียนของห้องทดลอง (ตรวจเลขที่ไม่ซ้ำ)
- [ ] สร้างงาน 2 งานสำหรับวันทดลอง: **งาน A** (ให้คะแนนเต็มทันที) และ **งาน B** (กรอกคะแนนทีละคน)
- [ ] **สำรองข้อมูลชุด #0** (ก่อนเริ่ม) เก็บไว้ในที่ปลอดภัย
- [ ] ซ้อมกู้คืนตาม `OPERATIONS.md` §5 บนเครื่องทดสอบ (ไม่ใช่ระบบจริง) — ตัวเลขต้องตรงทุกตัว

**บัตร QR**
- [ ] พิมพ์สติกเกอร์ **หนึ่งแผ่นก่อน** ด้วยเครื่องพิมพ์ที่จะใช้จริง แล้วสแกนทุกดวงด้วยทุกอุปกรณ์ที่จะใช้ — ดวงไหนอ่านยาก ให้พิมพ์ใหม่ (เพิ่มขนาด/ลดสติกเกอร์ต่อแผ่น)
  - ขนาด QR บนกระดาษของแต่ละแบบ: บัตร 10 ดวง ≈ 24 มม. · 21 ดวง (ค่าเริ่มต้น) ≈ 18 มม. · **40 ดวง ≈ 14 มม. (เล็กที่สุด — เสี่ยงที่สุด)**
  - ผมยังไม่มีเกณฑ์ "เล็กสุดที่อ่านได้" ที่เชื่อถือได้ สิ่งที่ทดสอบได้คือภาพสังเคราะห์ที่คมชัด ไม่เบลอ ไม่มีแสงสะท้อน (อ่านได้แม้ QR กว้างเพียง ~4% ของภาพ)
    ซึ่งเป็นกรณีที่ง่ายกว่าของจริงมาก **อย่านำไปตัดสินว่าสติกเกอร์ 40 ดวงใช้ได้** — ให้ดูจากผลสแกนบัตรพิมพ์จริงในตาราง §2 ของแบบบันทึก
  - ถ้าแบบ 21 ดวงอ่านได้ทุกดวงแต่แบบ 40 ดวงไม่ได้ ให้ใช้แบบ 21 ดวง อย่าแก้โค้ดกล้องเพื่อชดเชย จนกว่าจะเห็นบนเครื่องจริงว่ากล้องของเครื่องนั้นคือคอขวด
- [ ] ถ้าจะเคลือบบัตร: ทดสอบว่าแสงสะท้อนไม่ทำให้อ่านไม่ออก

**อุปกรณ์ (ทำกับ "ทุกเครื่อง" ที่จะใช้ในวันทดลอง)**
- [ ] เปิดผ่านลิงก์ `https://…` ตอนมีเน็ต แล้วรอจน ตั้งค่า → ทั่วไป → **ใช้ออฟไลน์ = พร้อม**
- [ ] iPad/iPhone: เพิ่มลงหน้าจอโฮม (แชร์ → เพิ่มลงในหน้าจอโฮม) แล้วเปิดจากไอคอน
- [ ] ตั้งค่า → อุปกรณ์และรหัสผ่าน → **ตรวจเครื่องนี้** ต้องได้ "พร้อมใช้งาน" (ข้อที่เป็น ▲ ให้อ่านและตัดสินใจ, ข้อที่เป็น ✘ ต้องแก้) แล้วกด "คัดลอกผลตรวจ" วางลงแบบบันทึก
- [ ] ตั้งค่า → การสแกน → **ทดสอบกล้อง** ผ่านทุกขั้น (แล้วลองสแกนบัตรจริงหนึ่งใบ)
- [ ] ตั้งค่า → การสแกน → **ทดสอบเครื่องยิง**: ยิงบัตรหนึ่งใบ ต้องขึ้นชื่อนักเรียน (ทำตอนแป้นพิมพ์เป็นภาษาไทยด้วย)
- [ ] **ซ้อมออฟไลน์ที่บ้าน:** เปิดโหมดเครื่องบิน → เปิดแอป → สแกน 3 ใบ (ป้าย "ค้าง 3") → ปิดโหมดเครื่องบิน → ป้ายต้องกลับเป็น 0
- [ ] ตั้งเวลาเครื่องเป็นอัตโนมัติ, ปิดโหมดประหยัดพลังงานที่ปิดหน้าจอเร็ว, ชาร์จเต็ม

**กระดาษ (บันทึกควบคู่)**
- [ ] ใบเช็คชื่อและใบคะแนนของห้อง มีคอลัมน์ **รหัสนักเรียน** (เพื่อพิมพ์เทียบทีหลัง) — แม่แบบ: `docs/trial/paper-*.template.csv`
- [ ] แบบบันทึกการทดลอง `docs/trial/TRIAL-LOG.md` พิมพ์ไว้

**ข้อมูลส่วนบุคคล:** ตรวจนโยบายโรงเรียนก่อนใช้ข้อมูลนักเรียนจริง (ถ้ายังไม่พร้อม ใช้ชื่อสมมติกับห้องทดลองได้ ผลด้านเทคนิคเหมือนกัน)

## 2. วันทดลอง

**กติกา:** กระดาษคือบันทึกจริงของวันนี้ ถ้าแอปมีปัญหา — **ทำต่อบนกระดาษ** จดเวลาและอาการลงแบบบันทึก อย่าลองซ้ำจนเสียคาบ
ห้าม deploy หรือกู้คืนข้อมูลระหว่างวัน (การกู้คืนกินโควตาเขียนเกือบทั้งวัน) — ถ้าต้องแก้บั๊กให้รอหลังเลิกเรียน

> หน้าจอขึ้น "ส่งแล้ว" หมายถึง **งานเก็บในเครื่องแล้ว** ไม่ใช่ถึงเซิร์ฟเวอร์แล้ว — ตัวชี้วัดคือป้ายมุมจอ: "ออนไลน์" ไม่มี "ค้าง N" = ถึงเซิร์ฟเวอร์ครบ

| ช่วง | ทำ | จดอะไร |
|---|---|---|
| เช้า | ตรวจเครื่องนี้ทุกเครื่อง (ข้อ 1) · **สำรองชุด #1** ยืนยันว่าดาวน์โหลดได้ | ผลตรวจเครื่อง |
| คาบเช็คชื่อ | เช็คชื่อ**ทั้งบนกระดาษและในแอป** (แตะเลือก) · ให้เด็กบางคนเช็คด้วยสแกน QR ถ้าใช้แบบสแกน | เวลาที่ใช้ต่อห้อง · ครั้งที่กดผิด/ต้องแก้ |
| คาบรับงาน (งาน A) | สแกนให้คะแนนเต็ม: ใช้**กล้องมือถือ**และ/หรือเครื่องยิงสลับกัน | ต่อบัตร: อ่านได้ในครั้งแรกไหม, นานแค่ไหน · ดวงที่อ่านยาก |
| คาบรับงาน (งาน B) | โหมดกรอกคะแนนทีละคน | เวลาต่อคน · พิมพ์คะแนนผิดไหม |
| **แบบฝึก A — เน็ตหลุด** | ระหว่างสแกน 5 คน ปิด wifi/เปิดโหมดเครื่องบิน 5 นาที แล้วเปิดกลับ | ป้าย "ค้าง N" ขึ้นตามจริงไหม · หลังเปิดเน็ตหายเป็น 0 ภายในกี่วินาที · มีรายการซ้ำ/หายไหม |
| **แบบฝึก B — บัตรมีปัญหา** | สแกนบัตรซ้ำ · บัตรของห้องอื่น · บัตรที่ออกใหม่แล้ว (เก่าถูกยกเลิก) · ลืมบัตร (พิมพ์เลขที่) | ข้อความบนจอเข้าใจไหม · ครูรู้ว่าต้องทำอะไรต่อไหม |
| **แบบฝึก C — แก้คะแนนผิด** | แก้คะแนนหนึ่งคนในสมุดคะแนน · กด "ล้างทั้งห้อง" ของงานทดลองแล้ว**ยกเลิกการล้าง** | คะแนนกลับมาเท่าเดิมไหม |
| **แบบฝึก D — สองเครื่องพร้อมกัน** | ให้สองเครื่องสแกนคนละคนพร้อมกัน แล้วสแกนคนเดียวกัน | ผลลัพธ์ถูกต้องไหม · มีข้อความขัดแย้งไหม |
| **แบบฝึก E — ปิดแอปกลางคัน** | สแกนตอนออฟไลน์ 3 คน → ปัดปิดแอป → เปิดใหม่ (ยังออฟไลน์) → ต่อเน็ต | คิวยังอยู่ไหม · ขึ้นเซิร์ฟเวอร์ครบไหม |
| เย็น | เปิดหน้ารายงานของห้อง · ส่งออก Excel · ดูรายการค้างส่ง · **สำรองชุด #2** | ตัวเลขในรายงานตรงกับกระดาษไหม |
| ก่อนกลับ | ทุกเครื่อง: ป้ายไม่มี "ค้าง" และไม่มีแถบ "ส่งไม่สำเร็จ" | ถ้ามี → ต่อเน็ตให้ส่งจนหมดก่อนกลับ จดไว้ |

## 3. หลังวันทดลอง — เทียบกับกระดาษ

1. พิมพ์กระดาษเป็นตาราง 2 ไฟล์ (Excel/Google Sheets แล้วบันทึกเป็น CSV หรือคัดลอกมาวางในไฟล์ข้อความ):
   `paper-scores.csv` (รหัส · งาน · คะแนน) และ `paper-attendance.csv` (วันที่ · รหัส · สถานะ) — ดูแม่แบบใน `docs/trial/`
   - คะแนน: ตัวเลข · `ส่ง` (ส่งแล้วยังไม่ให้คะแนน) · `ยกเว้น` · เว้นว่างหรือ `-` (ไม่ส่ง)
   - เช็คชื่อ: มา สาย ลา ป่วย ขาด · วันที่เป็น **ค.ศ.** รูปแบบ `2026-10-05`
2. ใช้ไฟล์สำรอง **ชุด #2** (ตั้งค่า → สำรองข้อมูล) แล้วให้ผู้ดูแลระบบรัน:
   ```bash
   npm run trial:reconcile -- --backup ngankrob-backup-2026-10-05.json \
        --scores paper-scores.csv --attendance paper-attendance.csv --csv differences.csv
   ```
   (ต้องมี Node.js — ถ้าครูไม่มี ให้ส่งไฟล์สำรองกับ 2 ไฟล์กระดาษให้ผู้ดูแลรัน; หรือเทียบจาก Excel ที่ส่งออกจากหน้ารายงานด้วยตา ซึ่งช้าและพลาดง่ายกว่า)
3. รายงานจะบอกทีละรายการว่าต่างอย่างไร: กระดาษมีแต่แอปไม่มี · แอปมีแต่กระดาษไม่ได้จด · ค่าไม่ตรง · จับคู่ไม่ได้ (พิมพ์รหัสผิด)
4. **ไล่ทีละรายการที่ไม่ตรง** เปิดต้นฉบับกระดาษ ตัดสินว่า "กระดาษจดผิด" หรือ "แอปผิด" แล้วลงแบบบันทึก
   - กระดาษผิด (พิมพ์ผิด/จดผิด): แก้ไฟล์กระดาษแล้วรันใหม่
   - แอปผิด: **นี่คือบั๊ก** — บันทึกขั้นตอนที่ทำให้เกิด เก็บไฟล์สำรองไว้ อย่าเพิ่งขยาย

ระบบซ้อมวงจรนี้ให้แล้วแบบอัตโนมัติ (`npm run e2e:rehearsal`): เช็คชื่อ + สแกนผ่านหน้าจอ → สำรองด้วยปุ่มจริง → เทียบกับกระดาษที่ถูกต้องต้องตรง 100%
และกระดาษที่ตั้งใจให้ผิดต้องถูกจับทุกจุด — เพื่อให้เชื่อได้ว่าถ้าวันจริงมีความต่าง มันคือความต่างจริง

## 4. เกณฑ์ผ่าน / ไม่ผ่าน

เกณฑ์เหล่านี้เป็น **ข้อเสนอเริ่มต้น** — ปรับกับครูเจ้าของห้องก่อนวันทดลอง อย่าปรับหลังเห็นผลแล้ว

**ต้องผ่านทุกข้อ (ไม่ผ่านข้อใดข้อหนึ่ง = ยังไม่ขยาย)**
1. **ไม่มีงานหาย:** ทุกรายการที่หน้าจอขึ้นสำเร็จ อยู่ในไฟล์สำรองชุด #2 (เทียบกระดาษ/บันทึกของครู)
2. **คะแนนและเช็คชื่อตรงกระดาษ 100%** หลังไล่ทุกความต่างแล้วพบว่าเป็นกระดาษผิด — ความต่างที่เกิดจากแอปแม้ข้อเดียว = ไม่ผ่าน
3. **แบบฝึก A และ E:** ทุกรายการที่ค้างตอนออฟไลน์ขึ้นเซิร์ฟเวอร์ครบ ไม่ซ้ำ ไม่หาย
4. **ตรวจเครื่อง** ทุกเครื่องไม่มี ✘ ก่อนเริ่ม
5. **ก่อนกลับ** ไม่มีรายการค้าง/ส่งไม่สำเร็จ ในเครื่องใดเลย (หรือมีแต่ส่งจนหมดได้ตอนต่อเน็ตและตรงกับข้อ 1–2)
6. ซ้อมกู้คืนก่อนวันทดลองตรงทุกตัวเลข

**ควรผ่าน (ไม่ผ่าน = ต้องมีแผนแก้ก่อนขยาย แต่ไม่ถึงกับหยุด)**
7. กล้องอ่านบัตรได้ในความพยายามครั้งแรก **ส่วนใหญ่** — ตัวเลขที่ยอมรับได้ให้ตกลงกับครู (ก่อนวัน) เก็บจำนวนที่อ่านไม่ได้จากแบบบันทึก
8. ครูทำแบบฝึก B–D ได้เองโดยอ่านข้อความบนหน้าจอ ไม่ต้องถามผู้ดูแล
9. เวลาเช็คชื่อทั้งห้องในแอปไม่ช้ากว่าบนกระดาษเกินกว่าที่ครูรับได้
10. ไม่มีการหมดโควตาฟรี (ดู dashboard ของ Cloudflare ท้ายวัน)

**ผล:** ผ่านทั้ง 1–6 → ขยายเป็น 2 ห้อง (ยังจดกระดาษคู่) 1 สัปดาห์ → แล้วจึงทุกห้อง · ไม่ผ่าน → แก้ → **ทดลองซ้ำ** ด้วยชุดเดิมของวันนั้น

## 5. สิ่งที่ควรรู้ว่าระบบทำอะไรเมื่อผิดปกติ (สำหรับผู้สังเกต)

| เหตุการณ์ | สิ่งที่ควรเห็น | ถ้าเห็นอย่างอื่น = จดเป็นบั๊ก |
