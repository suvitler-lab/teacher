# Visual design: รีวิวความสวยงามของ UI และไอคอนทั้งระบบ

โดย Web Designer · 2026-10-30 · อ้างอิง `ux.md` (UX/UI ตรวจความหมายไอคอน/microcopy/a11y ขนานกัน — เอกสารนี้เน้นความสวยงามและความสม่ำเสมอทางภาพ)

## แนวทาง

- 3 คำ: **สะอาด · เป็นระเบียบ · อุ่นใจ** (ครูมองแล้วรู้ทันทีว่า "ครบ/ค้าง/ผิด")
- คงไว้: IBM Plex Sans Thai, น้ำเงิน `#2f6fde`, โครง tokens.css, Tabler webfont, rail 64px / bottom tabs 5 ช่อง, เมนู 8 หน้า
- ข้อมูลที่ใช้ตรวจ: fixture ข้อมูลสมมติ (พอร์ต 4107, ปิดแล้ว PID 6136) — ภาพ 25 ไฟล์ใน `design/current/`
- **ข้อจำกัดหลักฐาน:** ภาพที่มี = 375 light (9: ทั้ง 8 หน้า + scan-round), 375 dark (8), 1024 light (8). **ไม่มี** 1024 dark และ desktop (>1024) เพราะ pane เบราว์เซอร์จำกัด 800×600 และเซสชัน fixture หมดอายุระหว่างถ่ายชุด dark 1024 (ภาพมี modal login ทับ จึงไม่เก็บ) — ผู้อ่านควรรู้ว่า desktop ใหญ่ประเมินจาก css ไม่ใช่ภาพ

## (ก) สิ่งที่ดีอยู่แล้ว — ต้องรักษา

1. ระบบสีสถานะสม่ำเสมอ: success/warning/danger/accent มีชุด `bg/text/fill/border` ครบทั้ง light/dark (tokens.css:31-35, 71-74) ข้อความบน bg สถานะผ่าน AA ทุกคู่ (5.2–8.6:1)
2. Dark mode ทำมาครบ: ตามเครื่อง + สลับเอง; ภาพ 375 dark อ่านง่าย ไม่มี element หลุดสี
3. Page header ใช้ pattern เดียวกัน: ไทล์ไอคอน 38px + ชื่อ + บรรทัดรอง (`ui.css:5-14`) ทุกหน้าหลัก
4. Home: ปุ่มหลัก "สแกนส่งงาน" เด่นด้วยพื้นน้ำเงินเต็ม, stat card มีสีไอคอนตามความหมาย (ภาพ home-375-light)
5. ไอคอนเป็นชุดเดียว (Tabler outline) ขนาดผ่านฟอนต์ ทำให้ stroke สม่ำเสมอ และ bundle เล็ก
6. Work-state cell (`ui.css:79-92`) แยกสถานะด้วยทั้งสีและรูปทรง/เส้นประ — ไม่พึ่งสีอย่างเดียว
7. Focus ring ของ input ชัด (`base.css:68-71`), `prefers-reduced-motion` ถูกเคารพ (`base.css:154`)
8. Bottom tabs + ปุ่มสแกนลอยกลาง เป็นจุดจำของแอปและเหมาะกับหัวแม่มือ

### ข2 App icon / favicon / maskable
- `favicon.svg`: สี่เหลี่ยมมุมโค้ง rx14 พื้นน้ำเงิน + ติ๊กสองตัว ตัวหลัง opacity .6. **ที่ 16–32px ติ๊กซ้อนกลายเป็นก้อนเดียว** (เส้น 5/64 ซ้อนทับ) และ ไม่มีความหมาย "งานครบ/ครู"
- `icon-maskable.svg`: เนื้อหาอยู่ในช่วง x 150–396 จาก 512 (≈48% กว้าง) — อยู่ใน safe zone 80% ปลอดภัย แต่ **ไอคอนเล็กเกินไป** บนหน้าจอโฮม iPad/Android และเป็นสีเรียบไม่มีมิติ
- manifest: ไม่มี PNG 192/512 และไม่มี `apple-touch-icon` ในที่ตรวจ — iOS (ผู้ใช้หลักคือ iPad) มักใช้ภาพ screenshot หน้าแทน SVG → **ความเสี่ยงสูง** (ต้องให้ Front-End/Tech Lead ยืนยัน index.html; ฉันไม่ได้อ่าน)
- **ข้อเสนอ:** เครื่องหมาย "ใบงานที่ติ๊กครบ": แผ่นกระดาษมุมพับสีขาว + ติ๊กน้ำเงินเข้มเดียว (ติ๊กใหญ่ ชัดที่ 16px) บนพื้นน้ำเงินไล่ระดับอ่อน `#3b7df0 → #2a63c9` (เหตุผล: ไล่สีเบาให้ดูเป็นแอปมืออาชีพ). Maskable ขยายเครื่องหมายเป็น ~62% ของพื้นที่. ส่งมอบเป็น SVG + PNG 192/512/180 (ให้ Front-End เป็นผู้นำเข้า `public/`). ตัวอย่างแสดงใน mockup overview.html (ส่วนหัว)

### ข5 Typography
- body 15px/1.5 (`base.css:12-13`) — **line-height ภาษาไทยควร ≥1.6** (สระบน/วรรณยุกต์ชิดบรรทัด; ภาพ attend-375 ชื่อ "ภูมิ" ชิดบรรทัดบน). เสนอ `1.6` เนื้อหา, หัวข้อ `1.35`
- มีเฉพาะน้ำหนัก 400/500 (`@fontsource ... 400,500`) — หัวข้อ/ตัวเลขใหญ่ (`.val 22px/500`) ไม่แยกจากเนื้อหาพอ; เสนอเพิ่ม 600 เฉพาะหัวหน้า/ตัวเลข stat (ต้องเพิ่ม `600.css` ซึ่งเป็นงานของ Front-End)
- ไม่มี type scale: ขนาด 10/11/12/13/14/15/16/17/19/20/22/24 กระจาย — เสนอ 12/13/15/17/20/24
- ตัวเลขตาราง `tabular-nums` ใช้แล้วในหลายที่ ดี (รักษา)

### ข6 สถานะว่าง / โหลด / ผิดพลาด
- Empty: `.uc-empty` (ไอคอน 30px สี muted) กับ `.empty` (shell.css:123) **สองสไตล์ซ้ำ**; หน้า Random ใช้กรอบเส้นประใหญ่ข้อความ "ยังไม่มีรายชื่อให้สุ่ม" ขนาดตัวใหญ่ 28px แข่งกับหัวข้อหน้า (ภาพ random-375) — ไม่มีไอคอน/ปุ่มนำทาง
- Loading: ใช้ `loader-2 spin` (22 จุด) แต่ไม่มี skeleton; กราฟิกกระโดดเมื่อข้อมูลมา (Reports/Gradebook)
- Error: ข้อความข้อผิดพลาดดิบอังกฤษ "Failed to register a ServiceWorker…" แสดงให้ครูเห็นในตั้งค่า (ภาพ settings-375) — ควรสรุปเป็นไทย + รายละเอียดพับได้ (เป็นเรื่องข้อความ→UX/UI)
- ป้ายสถานะ "ออฟไลน์/บันทึกแล้ว" (`.sync`) ดีและสม่ำเสมอ

### ข7 ความสม่ำเสมอข้ามหน้า
- หน้า "จบรอบสแกน" (summary) ไม่มี page header+ไทล์ไอคอนเหมือนทุกหน้า (ภาพจากทดสอบ: หัวข้อเปล่า ๆ)
- เมนูย่อยหน้าตั้งค่า (1024): รายการเรียงจัดชิดไม่เท่ากัน — "ทั่วไป/เวลาเรียน/การสแกน" กึ่งกลาง แต่ "ข้อมูลพื้นฐาน/อุปกรณ์และรหัสผ่าน/สำรองข้อมูล" ชิดซ้าย บางตัวเป็นสองบรรทัด (ภาพ settings-1024-light; ดู `settings.css`)
- แท็บยาวบนมือถือ (settings, gradebook chips) มี scrollbar เทาใต้แถบ (ภาพ settings-375, grade-375) — ซ่อน scrollbar + เฟดขอบขวาแสดงว่าเลื่อนได้
- ตัวเลือกวิชา/ประเภทในสมุดคะแนนใช้ `select` ของระบบ ขณะที่หน้าอื่นใช้ pill — 2 ภาษาภาพใน 1 แถบ
- ปุ่ม: สูง 38/36/34/32/30/26px หลายค่า (base.css, ui.css) — ควรสองขนาด 40 และ 32 (เล็ก)
- Scan setup มือถือ: หัวข้อ "1 เลือกงาน" ถูกบีบเป็น 2 บรรทัดข้างชิป "ทุกวิชา" (ภาพ scan-setup-375) — จัดชิปลงบรรทัดใหม่
- Scan round: การ์ดฟีดแบ็กดันเนื้อหาลงเมื่อสแกน (layout shift) (ภาพ scan-round-375-light) — จอง slot สูงคงที่

### ข8 Micro-interaction ที่คุ้มค่า (เบา ≤ 5; ทุกอันปิดเมื่อ reduced-motion)
1. สแกนสำเร็จ: การ์ดฟีดแบ็กเลื่อนลง 8px+fade 180ms และไฮไลต์ช่องเลขในผังด้วยแฟลชพื้นเขียว 600ms
2. Progress ring/bar ขยับค่าด้วย transition 300ms
3. ปุ่มกด: scale .98 (มีอยู่แล้ว) + เพิ่ม ripple เบา ๆ ไม่ต้อง — ให้พอแค่ transition สี 120ms ที่มี
4. Tab bar: ไอคอนที่เลือกขยับ translateY(-1px) + แถบสีเล็กใต้ไอคอน
5. Skeleton shimmer เมื่อโหลดรายงาน/สมุดคะแนน (ใช้ระหว่างรอ แทนวงกลมหมุน)
