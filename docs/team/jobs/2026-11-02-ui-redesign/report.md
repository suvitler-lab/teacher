# รายงานปิดงาน — ออกแบบหน้าบ้านใหม่ 8 หน้า (ui-redesign)

สถานะ: ลงโค้ดและปล่อยขึ้นระบบจริงแล้ว 4 พ.ย. 2569 (commits f405a43, 4dea5b8, 2780f8b บน `team/2026-11-04-ui-redesign`) · ไม่มี migration · API v9

## สิ่งที่สร้าง
- ทั้ง 8 หน้า (หน้าหลัก สแกน เช็คชื่อ สุ่มชื่อ สมุดคะแนน รายงาน นักเรียน ตั้งค่า) ตรงแบบ mockup รอบ 3 พร้อมสถานะ โหลด/ว่าง/ผิดพลาด, แป้นพิมพ์, ปุ่ม ≥ 44px, โหมดสว่าง/มืด
- layout การ์ดจอกว้าง (pageColumns / PageCols) และลิ้นชัก "ปรับการ์ด" ที่ซิงก์ทุกเครื่อง (key `*_cards`)
- สแกน: 3 โหมด, วันที่รับย้อนหลัง, แผ่นตัวเลือกช่อง (ให้คะแนน/ยกเลิกการส่ง + เลิกทำคงวันรับเดิม), ผังเลขที่, ฉายจอ (ซ่อนชื่อเด็กต่อเครื่อง)
- เช็คชื่อ: แตะซ้ำ = ยกเลิกการเช็ค + เลิกทำ 5 วินาที (API v9 `status:"none"`), "มาทั้งห้อง" ยืนยันก่อน, รวมข้อมูลช้ารายนักเรียน
- รายงาน: พิมพ์ A4 ตามการ์ดที่เปิด, คัดลอกข้อความ LINE, Excel 6 ชีต (คะแนนทุกงาน, คะแนนรวมตามประเภท, สรุปรายคน, คะแนนรายงาน, เช็คชื่อ, ภาพรวมห้อง)
- นักเรียน: นำเข้าไฟล์/วางข้อความ, สติกเกอร์ QR, ออก QR ใหม่
- ความเร็ว: cache ข้ามหน้าในหน่วยความจำ (swr), เมทริกซ์สถานะสมุดคะแนน, GET เช็คชื่อรวมรอบ D1
- login ถี่เกิน (429) ข้อความภาษาไทยแยกจากรหัสผ่านผิด

## ปัญหาที่ยังค้าง / ข้อจำกัด
- ยังไม่ได้ทดสอบบนอุปกรณ์จริง: เช็คชื่อ สมุดคะแนน เครื่องยิง/กล้อง และพิมพ์ A4 บนกระดาษ
- ขอบปุ่ม/ช่องกรอกในโหมดมืด (`--border`, `--border-strong`) ความคมราว 1.3–1.8:1 ยังไม่เปลี่ยน รอเจ้าของงานตัดสิน
- ข้อมูลสรุปรายงาน ~134 KB ยังไม่ลดขนาด
- Excel: ยังไม่ยืนยันกับโปรแกรมเปิดไฟล์ทุกตัว (ตัวเลขช่องส่งช้าหายในโปรแกรมบน iPad ก่อนเอาคอมเมนต์ออก)
- D40: `scan_sessions.mode` คือโหมดตอนเริ่มรอบ
- R-05 (รีวิว): `withdrawRows` ชนกับ flush ที่เพิ่งเริ่มข้ามแท็บ — ความเสี่ยงต่ำ ไม่แก้
- ข้อมูลที่เห็นอาจเก่าได้สูงสุดราว 20 วินาทีเมื่ออีกเครื่องแก้ (cache)
- ไม่ได้เปิด PR (เครื่องไม่มี `gh`)
