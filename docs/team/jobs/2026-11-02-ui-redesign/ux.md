## 1) ผู้ใช้ งานหลัก และ workflow

ครูประถมคนเดียว (D01) ใช้ iPad แนวตั้งยืนหน้าห้องเป็นหลัก (D28) มือถือ/คอมรอง · ทุกหน้าต้องใช้ได้แม้เน็ตหลุด (คิวใน outbox.ts/attSync.ts)

**สรุปเมนู: ยืนยัน 8 หน้า ชื่อเดิม (D22) จัด 4 กลุ่มตามจังหวะข้างบน** — วันนี้ (หน้าหลัก) · ในห้องเรียน (สแกน เช็คชื่อ สุ่มชื่อ) · ตรวจงาน (คะแนน รายงาน) · จัดการ (นักเรียน ตั้งค่า)
- เหตุผล: 3 หน้าในกลุ่ม "ในห้องเรียน" คือ 95% ของการแตะต่อวัน และต้องกดได้ขณะยืน → อยู่ติดกันใต้หน้าหลัก · rail แสดงที่ ≥ 721px (shell.css:78) จึงครอบ iPad แนวตั้ง 768 ด้วย — 8 รายการ + 3 ป้ายกลุ่ม + ซิงก์ + ออกจากระบบ สูงราว 560px พอดีจอ 768/1024 ไม่ต้องเลื่อน
- ลำดับใน rail เปลี่ยนจากเดิม (Shell.tsx:12-21: สแกน คะแนน เช็คชื่อ สุ่ม…) เป็น สแกน **เช็คชื่อ สุ่มชื่อ** แล้วค่อย คะแนน รายงาน — ย้าย "คะแนน" ออกจากตำแหน่งที่ 3 เพราะเป็นงานหลังเลิกเรียน
- มือถือ 5 แท็บคงเดิม (Shell.tsx:24 home · attendance · scan กลาง · gradebook · more) · ใน sheet "เมนู" ใช้ป้ายกลุ่มเดียวกัน (ในห้องเรียน: สุ่มชื่อ · ตรวจงาน: รายงาน · จัดการ: นักเรียน ตั้งค่า)
- **ไม่เพิ่มหน้า "งาน" (ยืนยัน PM)**: รายการงาน+สร้าง/ปิดรับ อยู่ในสมุดคะแนนแล้ว (`/gradebook?new=1`, Gradebook.tsx:85) และ DashboardPayload ไม่มีความคืบหน้าของงานที่ปิดแล้วที่ตรวจครบ (types.ts:252-253) → หน้า 9 ต้อง API ใหม่ · ให้ mockup มีสวิตช์ "ทางเลือกเมนู 9" ไว้ให้เจ้าของงานดูเทียบเท่านั้น

ลำดับความสำคัญ: (1) สิ่งที่ถ้าไม่ทำจะเสียข้อมูล/ผิด — ส่งไม่สำเร็จ, ค้างในเครื่อง, เทอมสิ้นสุด (2) ทางเข้างานในห้อง — ปุ่มลัด 4 ปุ่ม **ต้องวาดทันทีจาก bootstrap ไม่รอ dashboard** (Home.tsx:125-130 ทำแล้ว คงไว้) (3) ตัวเลขวันนี้ (4) การ์ดรายละเอียด
ปุ่มลัด 4 ปุ่มเท่ากัน ยืนยัน: สแกน (primary) · เช็คชื่อ · สุ่มชื่อ · สร้างงาน — เรียงตามความถี่ ไม่สลับตามเวลา (คาดเดาได้สำคัญกว่าฉลาด) · มือถือ 2×2 (home.css:3)
