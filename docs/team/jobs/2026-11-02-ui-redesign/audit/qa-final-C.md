## ตรวจแล้วถูกต้อง (ถึงตอนนี้)

  - ช่วง session หมดอายุ (401) หน้าต่าง "เข้าสู่ระบบอีกครั้ง" ขึ้น พร้อมข้อความ "มีข้อมูลรอส่ง 6 รายการ (เก็บไว้ในเครื่องแล้ว)" อีเมลเติมให้; ล็อกอินแล้วส่งเอง
  - ผลบนเซิร์ฟเวอร์: stu_1,2,3 = present, stu_4 = absent, stu_6 = absent (เปลี่ยนจาก present สำเร็จ), stu_5 ไม่มีแถว (ยกเลิกถูกต้อง), ไม่ซ้ำ 
- **ออฟไลน์ + แก้คะแนนสมุดคะแนน**: ป้ายบนเมนู "ออฟไลน์ · รอส่ง 1 → 2"; ช่องขึ้น "รอส่งขึ้นระบบ" (aria); outbox ใน IDB 2 รายการ
  - รีโหลดหน้าก่อนส่ง: คิวไม่หาย ส่งเองตอนบูต; เซิร์ฟเวอร์ได้ stu_1=7.5 (ทศนิยมรอด), stu_2=4 ครั้งเดียว
- **ออฟไลน์ + สแกนส่งงาน** (Worksheet 1, ให้คะแนนเต็ม): แตะ 3 คนตอนออฟไลน์ → ช่องขึ้น "รอส่งขึ้นระบบ", ป้าย "ออฟไลน์ · รอส่ง 3"; กด "ยกเลิกการส่ง" ของคนหนึ่งตอนออฟไลน์ → เข้าคิวเป็นรายการที่ 4 (ลำดับถูก)
- **รายการส่งไม่สำเร็จ**: ลบงานผ่าน API ("เครื่องที่สอง") ก่อนออนไลน์ → 4 รายการเข้า "ส่งไม่สำเร็จ" เหตุผลภาษาไทย "ไม่พบงานนี้แล้ว (อาจถูกลบ)", แบนเนอร์ "งานนี้ถูกลบแล้ว — สแกนแล้วจะไม่บันทึก…"; กด "ทิ้ง" ขึ้นกล่องยืนยัน ("เก็บไว้"/"ทิ้ง") — เก็บไว้แล้วรายการไม่หาย, ทิ้งแล้วหายทีละรายการถูกต้อง; ไม่มีข้อมูลหลุดไปบนเซิร์ฟเวอร์
- **สองเครื่อง (เช็คชื่อ)**: เครื่อง B (fetch ตรง) ตั้ง stu_10 = ขาด ก่อน; เครื่องนี้ออฟไลน์แตะ = มา → ออนไลน์: การ์ด "ข้อมูลชนกับอีกเครื่อง 1 รายการ · เครื่องนี้: มา · ในระบบ: ขาด (Chrome · Windows)" ปุ่ม "ใช้ของระบบ"/"ใช้ของเครื่องนี้"; ระหว่างรอเลือกเซิร์ฟเวอร์ยังเป็น "ขาด" (ไม่ทับเงียบ); "ใช้ของระบบ" → ขาดคงเดิม; ชนอีกรอบ stu_12 (B=ป่วย) "ใช้ของเครื่องนี้" → server = มา ถูกต้อง; แถวที่ไม่ชนในชุดเดียวกัน (stu_11) ส่งสำเร็จ
- **สำรองข้อมูล**: กด "ดาวน์โหลด" → กล่องเตือน PDPA "ก่อนดาวน์โหลดไฟล์สำรอง" → ไฟล์ ngankrob-backup-2026-11-04.json เป็น JSON ถูกต้อง (app=ngankrob, มี sha256 64 หลัก); จำนวน นักเรียน 52 (51 active+1 ย้าย) / ส่งงาน 841 / เช็คชื่อ 168 ตรงกับตารางบนเซิร์ฟเวอร์ที่อ่านแยก; 7.5 อยู่ในไฟล์
- **กู้คืน** (หลังแก้ไฟล์ให้ผ่านการตรวจ ดู B-1/B-2): ปุ่ม "กู้คืน" ปิดจนกว่าพิมพ์ "ยืนยัน"; ผลสำเร็จ "กู้คืนข้อมูลสำเร็จ"; data epoch 1→2; แถวที่เกิดหลังไฟล์ (stu_20 สาย) หายไป; คะแนน 7.5 รอด; ทดลองล้มเหลวแล้ว "ข้อมูลเดิมไม่ถูกเปลี่ยน" จริง (ตรวจ epoch และแถวไม่เปลี่ยน, กด ยกเลิก ล้างงานค้างได้)
- **เครื่องอื่น/เครื่องค้างงาน หลังกู้คืน**: เครื่องที่ส่งด้วย epoch เดิม ได้ 409 epoch_changed "ข้อมูลถูกกู้คืน… โหลดข้อมูลใหม่ก่อนทำต่อ"; หน้าเช็คชื่อเครื่องที่ค้างงานขึ้นแถบ "ข้อมูลถูกกู้คืนจากไฟล์สำรอง (อาจทำจากอีกเครื่อง) … รายการที่ค้างส่งจะถูกพักไว้ให้ตรวจสอบ" + ชิป "ต้องตรวจสอบ 1" ("ยังไม่ได้ส่ง ไม่ถูกลบ") — ไม่ถูกเขียนทับข้อมูลใหม่ (stu_30 ไม่มีบนเซิร์ฟเวอร์)

## บั๊ก (ชั่วคราว)
- B-1 (P2) ไฟล์สำรองที่แอปสร้างเองกู้คืนไม่ได้เมื่อมีส่งงานของนักเรียนห้องที่งานไม่ได้ผูกอยู่ (asg_hw: นร. ป.6/1 4 รายการ ผูกเฉพาะ ป.6/3) → execute ตอบ 422 invalid_backup / not_in_assignment_class. ชุดข้อมูลมาจาก seed แต่ทางเกิดจริง: แก้งานเอาห้องออก (assignments.ts removedClasses ปล่อยคะแนนห้องเดิมไว้) แล้วสำรอง-กู้คืน. ไฟล์: worker/lib/restore-validation.ts:98, worker/routes/assignments.ts
- B-2 (P2) ขั้น "ตรวจไฟล์" (validate) ผ่านและโชว์ตัวเลข แต่ execute มาปฏิเสธทีหลัง (หลังพิมพ์ยืนยัน + ดาวน์โหลดสำรองอัตโนมัติไปแล้ว): ข้อผิดพลาดตัวอย่าง method="later" (seed-demo.sql บรรทัด 138,145 — ไม่ใช่ค่าที่แอปเขียนเอง) และ B-1. ปลอดภัย (ไม่มีอะไรเปลี่ยน) แต่ UX ผิดหวัง. ควรให้ validate ใช้กฎชุดเดียวกับ execute
- **session หมดกลางใช้งาน** (POST /api/auth/logout ผ่าน fetch แล้วแตะเช็คชื่อต่อ): ขึ้นหน้าต่าง "เข้าสู่ระบบอีกครั้ง — เซสชันหมดอายุ — มีข้อมูลรอส่ง 3 รายการ (เก็บไว้ในเครื่องแล้ว)"; ล็อกอินใหม่แล้ว stu_31, stu_32 ขึ้นเซิร์ฟเวอร์ครบ ไม่หาย ไม่ซ้ำ
- **อุปกรณ์**: รายการอุปกรณ์ 5 รายการ, "เครื่องนี้" ไม่มีปุ่มออกจากระบบตัวเอง; ออกจากระบบเครื่องอื่นมีกล่องยืนยัน ('ออกจากระบบเครื่อง "iPad ห้องพักครู"? เครื่องนั้นต้องเข้าสู่ระบบใหม่') แล้ว revoked=1 + แจ้ง "ออกจากระบบเครื่องนั้นแล้ว"; ปุ่มออกจากระบบหลักเตือนงานค้าง "เช็คชื่อที่ยังไม่ได้ส่ง 1 รายการ … จะเก็บไว้และส่งให้เมื่อเข้าสู่ระบบใหม่" ตัวเลือก "อยู่ต่อ"
- **เปลี่ยนรหัสผ่าน**: รหัสเดิมผิด → "รหัสผ่านเดิมไม่ถูกต้อง"; รหัสใหม่สั้น → "รหัสใหม่อย่างน้อย 6 ตัว"; สำเร็จ "เปลี่ยนรหัสผ่านแล้ว" เครื่องนี้ยังอยู่ในระบบ เครื่องอื่นทั้งหมด revoked (เปลี่ยนกลับเป็นรหัสเดิมสำเร็จ)
- **แถบบันทึกตั้งค่า**: แก้ชื่อโรงเรียน → "แก้ไขแล้ว 1 รายการ ยังไม่บันทึก | ยกเลิก | บันทึก"; ยกเลิก = ค่าเดิมกลับมา; ออกจากหน้าโดยไม่บันทึก → กล่อง "ออกจากหน้านี้? … อยู่ต่อ / ออกโดยไม่บันทึก" (อยู่ต่อ คงหน้าและแถบ; ออก = ไม่บันทึกจริง ตรวจเซิร์ฟเวอร์); บันทึก = "บันทึกการตั้งค่าแล้ว" ค่าขึ้นเซิร์ฟเวอร์
- **ประวัติการแก้ไข**: ส่วนใหญ่เป็นภาษาไทย (สถานะ: มา · ชื่อ, เช็คชื่อ · ตาราง, กู้คืน) ยกเว้น B-3 ด้านล่าง
