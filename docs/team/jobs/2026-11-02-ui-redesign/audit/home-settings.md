# ตรวจโค้ดจริง เทียบสเปกออกแบบ: หน้าหลัก (Home) และ ตั้งค่า (Settings)

ตรวจ 3 พ.ย. 2569 · branch `team/2026-11-04-ui-redesign` · **อ่านโค้ดอย่างเดียว** (ไม่ได้เปิดเบราว์เซอร์ ไม่ได้รัน build/เทสต์) · ทุกข้อด้านล่างจึงเป็น "จากโค้ด" ยกเว้นที่ระบุว่ามีเทสต์ล็อก · เทียบกับ `brief.md` `ux.md` `design/home-notes.md` `round2-notes.md` `round3-notes.md`

## สรุป

1. สิ่งหลักของหน้าหลักครบและกดได้จริง: เมนู 4 กลุ่ม, การ์ด 9 ใบ (เปิด 5/ปิด 4 ตามที่ตกลง), ต้องทำตอนนี้, ปุ่มลัด 4, ตัวเลข 4, ซ่อนชื่อ, แผงปรับหน้าหลัก, ข้อความไทยตรงสเปกเกือบทั้งหมด, route ของการ์ดถูกต้อง
2. หน้าตั้งค่าทำครบโครง: การ์ด 5 ใบ + ปรับการ์ด, ป้ายขอบเขต "ทุกเครื่อง/เครื่องนี้เท่านั้น", สวิตช์บันทึกทันที + เลิกทำ, Dialog แทน `confirm()` (ออกจากหน้า/ออกจากระบบเครื่องอื่น), แก้สะกด "เช็คชื่อ", อีเมลอ่านอย่างเดียว
3. **บั๊กจริง 1 ข้อที่ผู้ใช้เจอแน่ (จากโค้ด): ในหน้าตั้งค่า พอกด "ปรับการ์ด" แล้วสลับการ์ด แถบ "แก้ไขแล้ว 1 รายการ ยังไม่บันทึก" โผล่เอง และถ้ากด "บันทึก" จะส่งค่าการ์ดเก่ากลับไปทับ** (ข้อ 1 ด้านล่าง)
4. ที่ยังขาด: แบนเนอร์ PDPA ในหมวดสำรองข้อมูล, toast "บันทึกแล้ว · ใช้ทุกเครื่อง" + การเก็บคิวตอนออฟไลน์ของแผงปรับการ์ด, skeleton ตอนโหลดหน้าหลัก, สถานะว่าง "ไม่มีห้อง/ไม่มีนักเรียน" แบบมีปุ่ม, a11y ของเมนูข้าง/แถบบันทึกตั้งค่า, `role=progressbar`
5. ผลนับ (รวมบรรทัดย่อยทั้งหมดในตาราง): ดูท้ายไฟล์ "ผลนับ"

คำอธิบายสัญลักษณ์: ✅ ทำแล้ว · ⚠️ ทำบางส่วน/ต่างจากสเปกเล็กน้อย · ❌ ยังไม่ทำ (หรือทำผิดทาง) · ➖ เลื่อนตามที่เอกสารระบุ

## ข้อสังเกตเรื่องที่ "กดได้จริง"

- ทุกปุ่ม/แถวที่สเปกให้กด **มี `onClick`/`href`** และไม่พบ element ที่บัง: ปุ่มลัด (`<a href>` 3 ตัว + `<button>`), ตัวเลข 4 ช่อง (`<button>`), แถวห้อง/นักเรียนในการ์ด (`<button>` เต็มแถว), ชิปในการ์ดงาน (`ChipButton`), หัวการ์ด "… ›" (`button.lk`), การ์ดตั้งค่าทุกปุ่ม
- ไม่พบ `disabled` ผิดเงื่อนไข: ▲▼ ปิดเฉพาะปลายสุด (`CardSettings.tsx:27-28`), "ดาวน์โหลด" ปิดเฉพาะ `busy`
- ที่ "ควรกดได้แต่กดไม่ได้": **ตัวแถวห้องในการ์ดงานที่กำลังเก็บ** (H20) และ **รายการ audit/อุปกรณ์ในการ์ดตั้งค่า** (เป็นข้อความ ไม่ใช่ปุ่ม; สเปก ux.md §2 ภาค 2 ให้ "ดูทั้งหมด" เท่านั้น จึงไม่ถือว่าขาด)
- ข้อจำกัดของการตรวจนี้: ไม่ได้ตรวจขนาดแตะ/contrast ด้วยการวัดในเบราว์เซอร์ (ตามคำสั่ง) ผล "≥44px/≥13px/สี" มาจากการอ่านกฎ CSS กลาง (`base.css:163-177`, `ui.css:98-101`, `tokens.css`) และควรยืนยันด้วยภาพจริงตอน Gate V
