# Requirements ส่วนที่ 12: คำตอบก่อนโครงหน้าหลัก

สถานะ: คำตอบ SA ก่อน T-34–T-36 · ไม่แก้ requirements เดิม (PM รวม) · อ้างอิง AC-20, BR-01, BR-12, D31

## Q-A งานไม่มีกำหนดส่งแต่มีคนค้าง ขึ้นชิป "ตามงานค้าง" หรือไม่

**ตอบ: ไม่ขึ้น (ในรอบนี้ ตามพฤติกรรมเดิม)** หลักฐาน:
- `shared/metrics.ts:51` `workState`: เป็น "ค้าง" (missing) เมื่องานปิดรับ หรือมีกำหนดและเลยกำหนดเท่านั้น งานเปิดรับที่ไม่มีกำหนด = "pending" ตลอด → `p.missing = 0` → `missingCount` ไม่นับ
- `homeLogic.ts:302-311` สร้างชิปจาก `openAssignments` ที่ `missing > 0` เท่านั้น จึงไม่มีทางได้ชิปของงานไม่มีกำหนด (ชิปมี `daysLate = 0` ได้เฉพาะงานที่ปิดแล้ว/ข้อมูลผิดปกติ ไม่ใช่งานเปิดรับ)
- D31/`shouldClose` (`homeLogic.ts:31`) ไม่ได้ทำให้เกิดชิป มันเพียงเปิดปุ่ม "ปิดรับงานนี้" บนชิปที่มีอยู่แล้ว ส่วน "ไม่มีกำหนด → เปิดมา ≥ 14 วัน" ใน AC-20 จึงใช้ได้เฉพาะงานที่เปิดรับและค้าง > 0 ซึ่งเกิดไม่ได้ตามข้างต้น = เงื่อนไขนี้ไม่มีผลบนหน้าหลักวันนี้ (ไม่ใช่บั๊ก; ตรงกับ D31 "คนที่ไม่เคยส่งงานไม่มีกำหนด นับเป็นค้างเมื่อปิดรับแล้ว")
- ผลต่อ AC-20: ชิปไม่มีกำหนดไม่ต้องทำและ **ห้ามแสดง** · QA: งาน W3 (ไม่มีกำหนด เปิดรับ ไม่มีใครส่ง) → ไม่ขึ้นชิป ไม่รวมใน `missingCount` (สอดคล้อง F-R38/FG1 "ยังไม่ถึง" ไม่ใช่ "ค้าง") · ปิดรับ W3 เมื่อใด → คนที่ไม่ส่งเป็น "ค้าง" และขึ้นชิป (โดย `daysLate` = 0 → แสดง "ค้าง X" ไม่แสดง "เลย N วัน")

## Q-B ค่าเริ่มต้นการ์ดต่อโครง (BR-12)

**ตอบ: ตรงกับเอกสาร ไม่ต้องแก้ค่า แต่ BR-12 เงียบเรื่องค่าเริ่มต้น จึงเพิ่มบรรทัดยืนยัน**
- `homeLayout.ts:17-24`: ก = open, follow, absent, due เปิด · `classes` ปิด · ข = follow, absent เปิด · ค = att, open, follow เปิด — ตรงกับรายการปรับได้ของ BR-12 และ ux.md:203-205 ครบทุกการ์ด
- design/preview.html โครง ก มีการ์ด "ความคืบหน้ารายห้อง" (บรรทัด 2706) แต่ **ไม่มีการ์ด "ห้องของฉัน"** (ค้นไม่พบในโฟลเดอร์ design) → ค่าเริ่มต้นปิดตรงกับภาพที่เจ้าของงานเห็นอนุมัติ (การ์ดซ้ำกับความคืบหน้ารายห้อง) เปิดเองได้ในลิ้นชัก
- เสนอเพิ่มท้าย BR-12: "ค่าเริ่มต้น: ก ปิด 'ห้องของฉัน' (ซ้ำกับความคืบหน้ารายห้อง; เปิดได้) · ข/ค เปิดทุกการ์ด · ผู้ใช้เดิมที่เคยปิดการ์ดในหน้าเดิม = เริ่มค่าเริ่มต้นใหม่ของแต่ละโครง" ตัวอย่าง: ผู้ใช้ใหม่เปิดโครง ก → เห็น 4 การ์ด ไม่เห็น "ห้องของฉัน" · เปิดสวิตช์ → เห็น 5 · สลับ ค → เห็น 3 การ์ดของ ค ครบ
- ไม่ใช่การตัดสินเชิงธุรกิจใหม่ (ใช้ค่าเดิม `OFF_BY_DEFAULT` ที่มีอยู่ก่อน) · ข้อควรระวัง: ถ้าเจ้าของงานเคยเห็น "ห้องของฉัน" ในหน้าเดิมแล้วอยากให้เปิด → เป็นการตัดสินของเจ้าของงาน (ค่าแนะนำ: คงปิด)

## Q-C ux "ลำดับความเร่งด่วน" ขัดกับ BR-01

**ตอบ: T-33 ใช้ BR-01 ถูกต้อง (requirements ชนะ ตามลำดับเอกสารของ job) และต้องแก้ ux.md ให้ตรง** — ความต่างเดียว: สิ้นสุดภาคเรียน ux = ลำดับ 3 (ก่อนเช็คชื่อ) · BR-01 = ลำดับ 7 (หลังตรวจงาน ก่อนสำรองข้อมูล) · นอกนั้นตรงกัน (ux ข้อ 4 เช็คชื่อ/5 ครบวันนี้/6 ตามค้าง/7 ตรวจงาน เท่ากับ BR-01 ข้อ 3/4/5/6)
- เหตุผลที่ BR-01 ถูก: เป็นฐานของตัวอย่างคำนวณ "5 อย่าง" และ T-33 มีเทสต์ `hr-homecore-logic` ตาม BR-01 แล้ว · ux.md บรรทัด 117-119 ระบุ "ไม่เปลี่ยนกฎ `todoRows`" ซึ่งต้องตรวจว่า `todoRows` เดิมเรียงอย่างไร (T-33 ว่ายังอยู่ใน LegacyBody) — ถ้า `todoRows` เดิมวางสิ้นสุดภาคเรียนก่อนเช็คชื่อ ux สะท้อนของเดิม แต่ requirements ที่เจ้าของงานอนุมัติ (Gate R) ระบุลำดับใหม่ชัดเจน
- **ไฟล์ที่ต้องแก้: `ux.md` บรรทัด 119** → "1 ส่งไม่สำเร็จ → 2 ค้างในเครื่อง → 3 เช็คชื่อห้องที่ยังไม่เช็ค → 4 ครบกำหนดวันนี้ → 5 ตามงานค้าง → 6 ตรวจงาน → 7 สิ้นสุดภาคเรียน → 8 สำรองข้อมูล" · `requirements.md` ไม่ต้องแก้
- ข้อสังเกต ไม่บล็อก: ux.md:110-115 ตารางปลายทางไม่ได้ระบุลำดับ จึงไม่ต้องแก้ · `visual-design.md` ให้ PM ตรวจว่ามีลำดับซ้ำหรือไม่ (SA ไม่พบจากการค้นคำ)
