## ผู้ใช้และงานหลัก

- ผู้ใช้: ครูคนเดียว สอนหลายห้อง (ปีการศึกษาเดียว) ใช้ **iPad เป็นหลัก** (ถือเดินในห้อง ใช้นิ้ว) · คอมที่โต๊ะครู · มือถือเป็นรอง · บางครั้งสะท้อนจอขึ้นทีวี (โหมดซ่อนชื่อ) · เน็ตโรงเรียนไม่แน่นอน
- งานหลักของหน้าหลัก (เรียงตามเวลาที่ครูใช้จริง):
  1. **เปิดมาเห็นทันทีว่าวันนี้ต้องทำอะไรก่อน** (เช็คชื่อห้องที่ยังไม่เช็ค, งานครบกำหนด, งานค้าง, ตรวจงาน, สำรองข้อมูล, ของที่ค้างส่งในเครื่อง)
  2. **กดปุ่มลัดเข้าห้องเรียนได้ในนิ้วเดียว** (สแกนส่งงาน · เช็คชื่อ · สุ่มชื่อ · สร้างงาน)
  3. **รู้ความคืบหน้างานแต่ละห้อง** (ส่งแล้ว/รอตรวจ/ค้าง) และ **รู้ว่าใครต้องติดตาม**
- หลักออกแบบ: (ก) ทุกตัวเลขที่เห็นกดต่อได้ไปยังหน้าเดิมที่มีรายละเอียด (ข) ข้อมูลทุกชิ้นมาจาก `GET /api/dashboard` (`DashboardPayload`) + ค่าในเครื่อง (outbox/attDrafts/backup) ที่แอปมีอยู่แล้ว — ส่วนที่ต้องเพิ่ม API ติดป้าย `ต้องเพิ่ม API` (ค) ตัวเลขและการคำนวณไม่เปลี่ยน ใช้ `todoRows`, `dueInfo`, `shouldClose`, `attendanceHeadline`, `uncheckedRooms` เดิม

## ลำดับข้อมูลและสิ่งที่กดได้ (ต่อจาก draft)

### ส่วนที่ใช้ร่วมทุกโครง (เหนือเนื้อหา)

ลำดับบนลงล่าง: **แถบบน** → (แบนเนอร์ปีเก่า ถ้ามี) → (แบนเนอร์ซ่อนชื่อ ถ้าเปิด) → เนื้อหาโครง

แถบบน (topbar) — แก้จาก draft ให้ครบกับแอปจริง:

| ปุ่ม | ทำอะไร | หมายเหตุ |
|---|---|---|
| วันที่ · ภาคเรียน (ข้อความ) | แสดงอย่างเดียว | |
| **เลือกภาคเรียน** (`TermPicker` เดิม) | เปลี่ยนภาคเรียน → โหลดแดชบอร์ดใหม่ | draft มีแล้ว เก็บ |
| **ซ่อนชื่อ** (toggle, `aria-pressed`) | เปิด/ปิดโหมดฉายจอ | **draft ไม่มี — ต้องเพิ่ม** (มีอยู่ในแอปจริง `hideNames`) ไอคอนตาเปิด/ตาปิด + ข้อความ "ซ่อนชื่อ"/"ซ่อนชื่ออยู่" (ไม่ใช้สีอย่างเดียว) |
| **ปรับหน้าหลัก** | เปิดลิ้นชักซ่อน/เรียงการ์ด | ดู §ปรับหน้าหลักในแต่ละโครง |

บนมือถือ: ปุ่มในแถบบนเหลือแต่ไอคอน (≥ 44×44) มี `aria-label` ครบ · วันที่ย่อ ซ่อน "ภาคเรียน" ตาม draft

ทักทาย: `สวัสดี <ชื่อครู>` ใช้ `teacher_name` จริง (ไม่มีชื่อ → "คุณครู") · ข้อความตามช่วงเวลา (เช้า/สาย/บ่าย/เย็น) เป็นแค่คำทักทาย ไม่ผูกกับตรรกะ

### โครง ก "วันนี้ของครู"

ลำดับ (บนจอกว้าง): hero → [ซ้าย: ลำดับงานวันนี้ | ขวา: ปุ่มลัด → ความคืบหน้ารายห้อง → ต้องติดตาม]

| บล็อก | เนื้อหา | กดได้ → ไปไหน |
|---|---|---|
| hero | คำทักทาย · **ตัวเลขใหญ่ "เหลือ N อย่างที่ต้องทำ"** (จุดเด่นเดียวของหน้า) · pill สรุป 4 อัน (เช็คชื่อแล้ว x/y ห้อง · ครบกำหนดวันนี้ · รอตรวจ · ค้างส่ง) | pill แต่ละอัน = ปุ่ม: เช็คชื่อ→`/attendance` · ครบกำหนด→`/gradebook` · รอตรวจ→ลิสต์ "รอตรวจ" (ลิ้นชักเดิม `ListKind=awaiting`) · ค้างส่ง→ลิสต์ "ยังไม่ส่ง" (`missing`) (ใน draft เป็นข้อความเฉยๆ — เปลี่ยนเป็นปุ่ม เพราะแอปเดิมกดได้) |
| ลำดับงานวันนี้ (timeline) | รายการจาก `todoRows` + ครบกำหนดวันนี้/ค้าง/รอตรวจ/พรุ่งนี้ เรียงตามความเร่งด่วน (ดู §ลำดับ) · แต่ละรายการ: หัวข้อ + เหตุผลหนึ่งบรรทัด + ปุ่มหลัก 1 ปุ่ม (+ปุ่มรอง 1) | ดูตาราง route ด้านล่าง |
| ปุ่มลัด 4 ปุ่ม | สแกนส่งงาน (เด่นสุด) · เช็คชื่อ · สุ่มชื่อ · สร้างงาน | ดู route |
| ความคืบหน้ารายห้อง | แถบ ตรวจแล้ว/รอตรวจ/ยังไม่ถึงกำหนด/ค้าง + % ส่ง ต่อห้อง | แถวห้อง = ปุ่ม → `/gradebook?class=<id>` |
| ต้องติดตาม | จัดกลุ่มตามจำนวนชิ้นที่ค้าง (สูงสุด 8 คน จาก API) | ชื่อ → `/students?class=<id>&student=<id>` · "ทั้งหมด" → `/reports` |

บนจอแคบ (≤ 1100px = iPad ตั้ง): คอลัมน์เดียว ลำดับ **hero → ปุ่มลัด 4 ปุ่มแถวเดียว (iPad ตั้ง) / 2×2 (มือถือ) → ลำดับงาน → ความคืบหน้า → ต้องติดตาม** (ปุ่มลัดขึ้นก่อน timeline เพราะใช้บ่อยที่สุดในห้องเรียน — ตรงกับ draft ที่ใช้ `order:-1`)

### โครง ข "แผงรายห้อง"

ลำดับ: หัว + สรุปบรรทัดเดียว → dock ปุ่มลัด (แถบสี 4 ปุ่ม) → แถบ "ต้องทำตอนนี้ N" (pill สูงสุด 3 + "อีก x อย่าง") → **แผงห้อง** → รายละเอียดห้องที่เลือก (งานที่เปิดรับ | ต้องติดตาม · ไม่มาวันนี้ · แนวโน้ม)

| บล็อก | พฤติกรรม |
|---|---|
| แผงห้อง (ปุ่ม `aria-pressed`) | กด = เลือกห้อง แสดงรายละเอียดด้านล่าง (ไม่เปลี่ยนหน้า) · ห้องที่เลือกมีเส้นขอบหนา + ไอคอน caret (ไม่ใช้สีอย่างเดียว) · ค่าเริ่มต้น = **ห้องแรกที่มีงานต้องทำ** (ยังไม่เช็คชื่อ/ค้างมากสุด) ไม่ใช่ห้องแรกในลิสต์เสมอ |
| ปุ่ม "สร้างงาน" ในรายละเอียด | → `/gradebook?new=1` (ส่ง class ที่เลือกไปเป็นค่าเริ่มต้นถ้า route รองรับ — ถ้าไม่ ก็ `?new=1` เฉยๆ) |
| ไอคอนสแกนต่อแถวงาน | → `/scan?asg=<id>&class=<id>` |
| แถวงาน/ตัวเลข ค้าง/รอตรวจ | → `/gradebook?class&subject&asg&rows=missing|awaiting` (เหมือนชิปเดิมใน cards.tsx) |
| ปุ่ม "เช็คชื่อ ห้องนี้" (เมื่อยังไม่เช็ค) | → `/attendance?class=<id>` |
| "อีก x อย่าง" | **ใน draft สลับไปโครง ค (data-set layout:c) — แก้**: ผู้ใช้ที่เลือกโครง ข ไม่ควรถูกเปลี่ยนโครง ให้เปิด **แผ่นรายการ "ต้องทำตอนนี้ทั้งหมด"** (ลิ้นชัก/แผ่นล่างบนมือถือ) แทน |

จำนวนห้อง 1–8: ≤ 3 ห้อง = แผงใหญ่ (วงแหวน % 132px); **4–8 ห้อง = แผงกะทัดรัด** (วงแหวนเล็ก 72px + ตัวเลขหลักเดียว 2 บรรทัด, 4 คอลัมน์บนคอม/นอน, 2 คอลัมน์บน iPad ตั้ง, 1 บนมือถือ) · บนมือถือที่เกิน 4 ห้อง แผงเป็น **แถวแนวนอนเลื่อนได้** (chip สลับห้อง ไม่ใช่ 8 การ์ดยาว) — กำหนดไว้ที่ §ข้อมูลเยอะ

### โครง ค "โฟกัสงานถัดไป"

ลำดับ: บรรทัดทักทายเล็ก → **การ์ดโฟกัสใหญ่ (งานที่ 1)** + คอลัมน์ "ต่อจากนี้" → ปุ่มลัด → ไทล์ (มาเรียนวันนี้ · งานแต่ละห้อง · ต้องติดตาม · แนวโน้ม)

| ปุ่มบนการ์ดโฟกัส | ทำอะไร |
|---|---|
| ปุ่มหลัก (ใหญ่ 56px, สีกลับ) | ทำงานนั้น → route ตามตาราง |
| ปุ่มรอง (ถ้ามี เช่น "คัดลอกรายชื่อไป LINE", "ปิดรับงานนี้") | การกระทำรองของงานนั้น |
| **ทำทีหลัง** | ย้ายงานนี้ไปท้ายคิว **เฉพาะรอบนี้ (จำในหน้าจอ ไม่บันทึก)** · มี `aria-live` แจ้ง "ย้าย … ไปท้ายคิวแล้ว" |
| ~~เสร็จแล้ว~~ | **เสนอให้เอาออก** (ดู §ปัญหาใน draft ข้อ 1) |
| รายการ "ต่อจากนี้" (ปุ่ม) | กด = ดึงงานนั้นขึ้นมาเป็นโฟกัส (ไม่เปลี่ยนหน้า) |
| จุดความคืบหน้า (dots) | ประกอบอย่างเดียว `aria-hidden` · ข้อความ "ถัดไป · 2 จาก 5" เป็นตัวบอกจริง |

**ตำแหน่ง:** เพิ่มส่วน `appearance` "หน้าตา" (ไอคอน palette) ใน `SECTIONS` ของตั้งค่า ต่อจาก "ทั่วไป" · **เสนอให้ย้าย** ตัวเลือกสว่าง/มืด/ตามเครื่อง + ขนาดตัวอักษร + ความหนาแน่น ที่ตอนนี้อยู่ใน "ทั่วไป" มารวมที่นี่ (ครูหาที่เดียว) ← *เจ้าของงานตัดสินที่ Gate 1* (ค่าแนะนำ: ย้าย และทิ้งลิงก์ "ย้ายไป หน้าตา ›" ใน ทั่วไป หนึ่งเวอร์ชัน)

### เลย์เอาต์ของส่วน

บนคอม/iPad นอน: 2 คอลัมน์ — ซ้าย **ตัวเลือก** · ขวา **ตัวอย่างสด** (sticky) · iPad ตั้ง/มือถือ: ตัวอย่างขึ้นก่อน (ย่อ ~220px สูง) แล้วตัวเลือกด้านล่าง

ลำดับตัวเลือก (ลำดับ focus ตามนี้):

1. **โครงหน้าหลัก** — การ์ดเลือก 3 ใบ (radio group, `role=radiogroup`) แต่ละใบ = **ภาพย่อ** ของโครงจริง (SVG เรียบ ใช้สีธีมที่เลือกอยู่) + ชื่อ + คำอธิบายสั้น:
   - ก **วันนี้ของครู** — "ไล่งานตามลำดับของวัน เหมาะกับคนที่อยากเห็นภาพรวมทั้งวัน"
   - ข **แผงรายห้อง** — "ดูทีละห้อง เหมาะกับครูที่สอนหลายห้อง"
   - ค **โฟกัสงานถัดไป** — "ทีละเรื่อง ใหญ่ ชัด เหมาะกับใช้ในห้องเรียน"
2. **ธีม** — การ์ด 3 ใบ (radio): มืออาชีพ · อบอุ่น · สดใส · แต่ละใบแสดง **แถบสี 4 ช่อง + ตัวอย่างอักษร "กขค 123"** ด้วยฟอนต์ของธีมนั้น + คำบรรยาย 1 บรรทัด ("สะอาดตา จริงจัง" / "นุ่มนวล เป็นกันเอง" / "สดใส มีชีวิตชีวา")
3. **สว่าง / มืด / ตามเครื่อง** — segmented 3 ปุ่ม (radio) · ค่าเดิมของแอป (`ThemeChoice`) ใช้ต่อ
4. (ถ้ารวม) ขนาดตัวอักษร · ความหนาแน่น (ตัวควบคุมเดิม)
5. ปุ่ม **คืนค่าเริ่มต้น** (มีขั้นยืนยัน) — ค่าเริ่มต้นสมมติ = ธีมมืออาชีพ · โครง ก · ตามเครื่อง (ยืนยันที่ Gate 1, brief ยังไม่ระบุ)

ตัวเลือกที่เลือกอยู่: ขอบหนา + **เครื่องหมายถูกในวงกลมมุมการ์ด + ข้อความ "ใช้อยู่"** (ไม่ใช้สีอย่างเดียว)

### Flow 1: เปลี่ยนโครง/ธีม

1. ครูเปิด `ตั้งค่า > หน้าตา` → เห็นตัวเลือกปัจจุบันถูกเลือกไว้ + ตัวอย่างสดตรงกับสิ่งที่ใช้อยู่
2. แตะการ์ด "สดใส" → **ตัวอย่างเปลี่ยนทันที** (ภายใน 1 เฟรม ไม่ต้องกดปุ่มใด) ส่วนอื่นของหน้าตั้งค่าและทั้งแอปเปลี่ยนตามทันที (ดูตัวอย่างจริง)
3. ระบบ **บันทึกทันที** (ไม่มีปุ่ม "บันทึก" — สอดคล้องกับ "ปรับหน้าหลัก" เดิมที่บันทึกทุกครั้งที่แตะ) · ข้างหัวข้อแสดงสถานะ: "กำลังบันทึก…" → "บันทึกแล้ว · ใช้กับทุกเครื่อง" (`aria-live=polite`)
4. แตะ "แผงรายห้อง" → ตัวอย่างแสดงโครง ข → ปุ่ม **ไปดูหน้าหลัก** (ใต้ตัวอย่าง) → `/home`

| **ออฟไลน์** | ใช้ค่าใหม่ในเครื่องทันที ใส่คิวส่งตอนมีเน็ต (กลไก outbox เดิม) · ชิปสถานะเทา/เหลือง ไอคอน wifi-off | "ออฟไลน์ — บันทึกในเครื่องนี้แล้ว จะส่งให้เครื่องอื่นเมื่อมีเน็ต" |
| ขัดแย้งกับเครื่องอื่น (🔄) | ค่าล่าสุดชนะ · เครื่องอื่นเห็นค่าใหม่ตอนโหลดครั้งถัดไป ไม่เปลี่ยนกลางจอระหว่างใช้งาน | (ไม่มีข้อความรบกวน) |
| ค่าที่เก็บเสีย/ไม่รู้จัก (เช่นธีม "เรียบหรู" จากเครื่องเก่า) | ถอยกลับค่าเริ่มต้นแบบเงียบ | — |

## "ปรับหน้าหลัก" (ซ่อน/เรียงการ์ด) อยู่ตรงไหนในแต่ละโครง

ลิ้นชักเดิม `CardSettings` ใช้ต่อ — ปุ่ม **ปรับหน้าหลัก** อยู่ที่แถบบนทุกโครง (ตำแหน่งเดียวกัน จำง่าย) · แต่ **สิ่งที่ปรับได้ต่างกันตามโครง**:

| โครง | ปรับได้อะไร | ปิดไม่ได้ (ล็อก) |
|---|---|---|
| ก | การ์ดฝั่งขวา/ล่าง: ความคืบหน้ารายห้อง · ต้องติดตาม · ไม่มาวันนี้ · ครบกำหนด · ห้องของฉัน ฯลฯ (การ์ดเดิมที่ map เข้ามาได้) | ลำดับงานวันนี้ · ปุ่มลัด · ตัวเลขสรุปใน hero |
| ข | การ์ดในรายละเอียดห้อง: ต้องติดตาม · ไม่มาวันนี้ · แนวโน้ม (ถ้ามี API) | dock ปุ่มลัด · แถบต้องทำ · แผงห้อง |
| ค | ไทล์ด้านล่าง: มาเรียนวันนี้ · งานแต่ละห้อง · ต้องติดตาม · แนวโน้ม | การ์ดโฟกัส · ต่อจากนี้ · ปุ่มลัด |

- หัวลิ้นชักบอกโครงที่ใช้อยู่: "ปรับหน้าหลัก · โครง ข แผงรายห้อง" และแสดงเฉพาะการ์ดที่โครงนั้นมีจริง (การ์ดของโครงอื่นไม่ปรากฏ ไม่ให้งง)
- ข้อความล็อกแก้ตามโครง (ข้อความเดิม: "ปิดไม่ได้: ต้องทำตอนนี้ · ปุ่มลัด · ตัวเลข 4 ช่อง")
- ท้ายลิ้นชักเพิ่มลิงก์ "เปลี่ยนโครง/ธีมที่ ตั้งค่า > หน้าตา ›" → `/settings?section=appearance` (ปิดลิ้นชักก่อนไป)
- ตั้งค่าการ์ดของโครงหนึ่งแยกเก็บจากอีกโครง (เปลี่ยนโครงแล้วกลับมา การซ่อน/เรียงยังอยู่) — **ต้องให้ SA/Tech Lead ยืนยันว่าเก็บแบบแยกต่อโครงได้**; ทางเลือกถ้าไม่ได้: ใช้ชุดเดียวกันแล้วซ่อนการ์ดที่โครงนั้นไม่มี
- ลิ้นชักเดิมมี: สวิตช์ ซ่อน/แสดง (label "แสดงการ์ด …"), ปุ่ม ↑ ↓ (≥ 44px), `aria-live` บอกผล, "คืนค่าเริ่มต้น" มียืนยัน, ปุ่ม **เสร็จ** — **คงทั้งหมด** · ไม่ใช้ลากวาง (ลากเป็นทางเลือกเสริมได้ แต่ ↑↓ ต้องยังใช้ได้เสมอ ♿)

## เมนูซ้าย (rail) และแถบล่างมือถือ ในชุดหน้าตาใหม่

เมนู 8 หน้าเดิมและลำดับกลุ่มเดิม (วันนี้ · ในห้องเรียน · ตรวจงาน · จัดการ) **ไม่เปลี่ยนชื่อ ไม่เปลี่ยนลำดับ** (D22)

| ส่วน | ข้อกำหนด |
|---|---|
| rail (แท็บเล็ต/คอม) | กว้าง `max(92px, 5.4×fs)` · ไอคอน 24px + ป้ายใต้ไอคอนเสมอ (ไม่ใช้ไอคอนล้วน) · รายการสูง ≥ 44px · หน้าปัจจุบัน = พื้นสี + ตัวหนา + `aria-current="page"` (ไม่ใช้สีอย่างเดียว) · เส้นคั่นกลุ่มเป็น `aria-hidden` · ท้าย rail: สถานะซิงก์ (จุด + คำ "ออนไลน์"/"ออฟไลน์"/"รอส่ง n") + ออกจากระบบ (ยืนยันถ้ามีค้างในเครื่อง — กลไกเดิม `doLogout`) |
| แถบล่างมือถือ | 5 ปุ่ม: หน้าหลัก · เช็คชื่อ · **สแกน (ปุ่มกลางยกสูง)** · คะแนน · เพิ่มเติม — เหมือนเดิม · ปุ่มสูง ≥ 44px กว้าง ≥ 56px · แท็บปัจจุบัน = สี + ตัวหนา + (เสนอ) แถบสั้นด้านบนปุ่ม · เว้นขอบล่างปลอดภัยของ iPhone (`env(safe-area-inset-bottom)`) |
| "เพิ่มเติม" | แผ่นล่างเดิม จัดกลุ่มเหมือน rail (สุ่มชื่อ · รายงาน · นักเรียน · ตั้งค่า) · เปิดด้วยปุ่ม ปิดด้วยปุ่ม "ปิด" + แตะนอกแผ่น + Esc |
| ธีมต่างกัน | เปลี่ยนเฉพาะ token (สีพื้น rail, สี active, รูปทรง/เงา) · **โครงสร้างและตำแหน่งปุ่มเหมือนกันทุกธีม** ครูจึงไม่หลงเมื่อเปลี่ยนธีม |
| motion | hover/active ของ rail ≤ 150ms · ห้ามมีอนิเมชันค้างใน rail |

## การเข้าถึง (accessibility) ♿

**ลำดับ focus / คีย์บอร์ด** (ตามลำดับ DOM ไม่ใช้ `tabindex` > 0)
1. (ลิงก์ข้ามไปเนื้อหา "ข้ามไปเนื้อหาหลัก" — เสนอเพิ่ม ปรากฏเมื่อโฟกัส)
2. เมนูหลัก (rail/แถบล่าง) → 3. แถบบน (ภาคเรียน · ซ่อนชื่อ · ปรับหน้าหลัก) → 4. แบนเนอร์ (ถ้ามี) → 5. **ก:** hero pill → ปุ่มลัด → timeline (ตามลำดับเวลา: เช็ค → ปุ่มหลัก → ปุ่มรอง ต่อรายการ) → ความคืบหน้า → ต้องติดตาม · **ข:** ปุ่มลัด → แถบต้องทำ → แผงห้อง (ลูกศรซ้าย/ขวาย้ายระหว่างแผง ถ้าเป็น radiogroup) → รายละเอียด · **ค:** โฟกัส (ปุ่มหลัก → รอง → ทำทีหลัง) → ต่อจากนี้ → ปุ่มลัด → ไทล์
- ตำแหน่งภาพ = ลำดับ DOM (ก: บนมือถือ/ตั้ง ปุ่มลัดอยู่ก่อน timeline → ใน DOM ต้องอยู่ก่อนด้วย ไม่ใช้ `order` CSS ที่ทำให้ focus กระโดด)
- focus ring: เส้นหนา 3px สี `--text-accent` + offset 2px ใช้ได้ทั้ง 3 ธีม สว่าง/มืด (ธีมสดใสต้องไม่ถูกเงาออฟเซ็ตทับ)
- ลิ้นชัก/แผ่นล่าง/แผ่น "ต้องทำทั้งหมด": ย้าย focus เข้าไปข้างใน, วน focus ในกรอบ, Esc ปิด, คืน focus ไปปุ่มที่เปิด
- แผงห้อง (ข) = ปุ่ม `aria-pressed` (หรือ radiogroup) พร้อม `aria-label` สรุป ("ป.6/1 ส่งงาน 78% ยังไม่ได้เช็คชื่อ แตะเพื่อดูรายละเอียด") · เมื่อเลือกห้อง รายละเอียดเป็น `region` มี `aria-labelledby` · ไม่ย้าย focus อัตโนมัติ (แค่ `aria-live` บอก)

**label ทุกช่อง:** ปุ่มไอคอนล้วนทุกปุ่มมี `aria-label` (เช็ค "ทำเสร็จแล้ว: …", สแกนต่อแถวงาน "สแกนรับ {งาน} {ห้อง}", ซ่อนชื่อ, ปรับหน้าหลัก) · การ์ดเลือกโครง/ธีมเป็น `radio` จริง มี `<label>` ครอบ · ภาพย่อโครง/ภาพประกอบ `aria-hidden` ใส่ `alt` ผ่านข้อความชื่อ · วงแหวน/แถบ/กราฟมี `role=img` + ข้อความตัวเลขทั้งหมดใน `aria-label`

**contrast (ตรวจจาก token ใน draft แล้ว — ตัวเลข = อัตราส่วน):** ข้อความหลัก/รอง/muted บนพื้นการ์ดผ่านทุกธีมที่ตรวจ (≥ 5.4 สว่าง, ≥ 6.1 มืด) · hero-muted บน hero ผ่าน (≥ 6.4) · rail-label ผ่าน (≥ 5.7) · text-warning/danger บน bg ผ่าน (≥ 5.5) · ปุ่ม on-accent ผ่าน (pro 6.25, warm 5.45, playful 5.12) · เส้นขอบควบคุม `--border-control` ≥ 3:1 (pro 3.06, warm 3.35 — **ใกล้ขีด ห้ามอ่อนลง**) · **ที่ไม่ผ่าน: ดู §ปัญหาข้อ 3** · Web Designer ต้องตรวจซ้ำทุกคู่ใน mockup สุดท้าย รวมโหมดมืดของ warm/playful ที่ยังไม่ได้คำนวณ

**ไม่สื่อด้วยสีอย่างเดียว:** สถานะเช็คชื่อ (มา/สาย/ลา/ป่วย/ขาด) มีไอคอน+คำเสมอ · แถบความคืบหน้ามี legend คำ + ตัวเลข ("ค้าง 4") ไม่ใช่แค่ส่วนสีแดง · ห้องที่เลือกมีขอบหนา+เครื่องหมาย · งานที่ทำแล้ว: ขีดฆ่า + ไอคอน check + คำ "ทำแล้ว" · เส้นเวลา "ตอนนี้" มีป้ายคำ · ธีมสดใสห้ามแยกห้องด้วยสีอย่างเดียว (ชื่อห้องเป็นตัวบอกหลัก สีเป็นของตกแต่ง)

**เป้ากด ≥ 44px (ทุกอุปกรณ์สัมผัส; draft ใช้ `--tap:44px`):** ปุ่ม, วงกลมเช็ค (44), ปุ่มไอคอน (44), `.person` (min 44), `.nx` (min 60), ปุ่ม ↑↓ ในลิ้นชัก (44), ปุ่มแถวความคืบหน้ารายห้อง (min 48) · ช่องว่างระหว่างเป้ากด ≥ 8px ในกลุ่มที่แน่น (ปุ่มรอง/ทำทีหลัง บน iPad) · ตัวอักษรต่ำสุด 13px (`--t-xs`) แต่ **ข้อความที่ครูต้องอ่านเพื่อตัดสินใจ (เหตุผลของงาน, ชื่อ) ≥ 15px** บน iPad

**reduced-motion:** `@media (prefers-reduced-motion: reduce)` ปิดทุก transition/animation/smooth-scroll (draft มีแล้ว — คงไว้ และต้อง **ใช้ได้ในแอปจริง ไม่ใช่เฉพาะ preview**) · motion ปกติ (เล็กน้อยตามเจ้าของงาน): การ์ดเด้งขึ้น 2px เมื่อ hover/กด ≤ 150ms · วงแหวน/แถบเติมค่า 600ms ครั้งเดียวตอนโหลด · สลับโครง/ธีม fade ≤ 200ms · ห้ามมีอนิเมชันวนซ้ำ ไม่มีสิ่งใดกะพริบ > 3 ครั้ง/วินาที · ความหมายต้องครบแม้ไม่มี motion

**อื่น ๆ:** `lang="th"` · line-height ≥ 1.6 กับข้อความไทยทุกขนาด (ตรวจ hero ตัวเลขใหญ่และหัวข้อที่ใช้ฟอนต์ display ของธีมอบอุ่น/สดใสที่ตัวอักษรสูง) · ซูมตัวอักษรของระบบได้ถึง 200% โดยไม่ทับ · เนื้อหาไม่ขึ้นกับ hover · `aria-busy` ระหว่างโหลด · ภาพประกอบไม่บังข้อความ (ที่มือถือ `padding-right` ที่หัวข้อ)
