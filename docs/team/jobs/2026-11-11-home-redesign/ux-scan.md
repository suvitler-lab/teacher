# UX: หน้าสแกนส่งงาน (ภาษาโครงเดียวกับหน้าหลัก) — รอบออกแบบที่ 2

โดย UX/UI Designer · 2026-11-11 · อ้างอิง `brief.md §รอบออกแบบที่ 2` · `ux.md` (หน้าหลักที่อนุมัติ) · `visual-design.md` (token 3 ธีม, Phosphor) · ยังไม่มี `requirements.md` ของหน้าสแกน — ใช้ AC ชั่วคราว **S1–S12** ให้ SA แมปกลับ

สำหรับ Web Designer: ทำ mockup เต็มใน `design/preview.html` **ห้ามเรียบ** — หน้าสแกนต้องมีจุดเด่นเท่าหน้าหลัก: hero สีของธีม + วงแหวนใหญ่ + การ์ดผลสแกนล่าสุดขนาดใหญ่ที่เปลี่ยนสีตามผล + ตารางเลขที่มีไอคอนต่อช่อง · เอกสารนี้กำหนด "ลำดับ พฤติกรรม สถานะ ข้อความ เสียง การเข้าถึง" ไม่กำหนดสี/ฟอนต์ (ใช้ token เดิม) · ใช้ชื่อสมมติ

## ผู้ใช้และงานหลัก

- ครูคนเดียว สอนหลายห้อง ยืนหน้าห้อง **ถือกองงาน มือหนึ่งถือกระดาษ อีกมือถือเครื่องอ่าน/iPad** สแกนรับงานทีละคน อาจต่อเครื่องอ่าน QR (HID), ใช้กล้อง, หรือพิมพ์เลขที่ · เน็ตโรงเรียนไม่แน่นอน · บางครั้งสะท้อนจอขึ้นทีวี
- งานหลัก: (1) เริ่มรอบเร็ว — งานใกล้ครบกำหนดถูกเลือกไว้ให้ (2) ยิงแล้วรู้ผลทันทีโดยไม่ต้องมอง — เสียง + สั่น + การ์ดใหญ่ (3) รู้ว่าใครยังไม่ส่งก่อนจบรอบ (4) จบรอบแล้วรู้ต้องทำอะไรต่อ
- หลักออกแบบ: (ก) ช่องรับเลขพร้อมรับเสมอ (ข) ทุกผลสแกน = ไอคอน + คำ + เสียง/สั่น ไม่ใช้สีอย่างเดียว (ค) ข้อมูลจากที่แอปมีอยู่ — ส่วนที่ต้องเพิ่มติดป้าย `ต้องเพิ่ม API`/`ใช้ข้อมูลเดิม` (ง) ไม่เปลี่ยนการตัดสินเดิม: ตารางเลขที่ 5 สถานะ (D28–D30), ยืนยันก่อนแก้/ยกเลิก (D16), ยกเว้นต้องถาม (D33), เด็กไม่ active ห้ามรับ (D15), สลับโหมดไม่อัปเดตเซิร์ฟเวอร์ (D40)

## ช่วงที่ 1: ตั้งรอบ (หน้าจอ A)

**ลำดับข้อมูล:** แถบบน → หัวหน้า "สแกนส่งงาน" + คำรอง → (แบนเนอร์: ปีเก่า/ซ่อนชื่อ) → ขั้น 1 เลือกงาน → ขั้น 2 เลือกห้อง → ขั้น 3 วิธีให้คะแนน → **แถบเริ่มติดล่าง** (สรุป "รอบนี้: <งาน> · <ห้อง> · เต็ม 20 · ให้คะแนนเต็ม" + ปุ่ม "เริ่มสแกน ป.6/1")

| ขั้น | เนื้อหา | กดได้ | หมายเหตุ |
|---|---|---|---|
| 1 เลือกงาน | การ์ดงาน (สูงสุด 5, "ดูทั้งหมด (n)") เรียงใกล้ครบกำหนดสุดก่อน · ในการ์ด: ประเภท(ไอคอน+คำ) · วิชา · เต็ม · **ส่งแล้ว x/y ต่อห้อง** · ครบกำหนด (ไอคอนปฏิทิน + "วันนี้/อีก 2 วัน/เลยกำหนด" เป็นคำ) · ชิปกรองวิชา ถ้ามี > 1 วิชา | แตะการ์ด = เลือก (`aria-pressed` + ✓ มุมการ์ด + ขอบหนา) | งานแรกถูกเลือกไว้ · งานที่เลือกอัปเดตเลขสด |
| 2 เลือกห้อง | ชิปห้องของงานนั้น + "ส่งแล้ว x/y · ยกเว้น n" | แตะ = เลือก (✓ + ขอบหนา) | งานห้องเดียว = ชิปเดียวถูกเลือกแล้ว |
| 3 วิธี | 3 การ์ด: ให้คะแนนเต็ม ("ยิงแล้วได้เต็มทันที") · กรอกทีละคน ("ยิงแล้วพิมพ์คะแนน") · รับงานก่อน ("ตรวจแล้วค่อยให้คะแนน") | แตะ = เลือก | ค่าเริ่มต้น "ให้คะแนนเต็ม" |
| เริ่ม | ปุ่ม primary สูง ≥ 56px · ข้างๆ ไอคอน เครื่องยิง/กล้อง (บอกว่ารองรับ) | → `startSession` → หน้า B | ไม่ครบ = disabled + เหตุผลข้างปุ่ม ("เลือกงานก่อน/เลือกห้องก่อน", `role=status`) |

**ต่อรอบเดิม (ทำรอบต่อจากครั้งก่อน):** รอบที่ค้างอยู่ถูกเก็บในเครื่อง (`scanSession`) — เปิดแอปมาแล้วเข้าหน้า B ทันที (พฤติกรรมเดิม) · เพิ่มแถบบนสุดของหน้า B **"ต่อรอบเดิม · <งาน> · <ห้อง> — ส่งแล้ว x จาก y"** ปุ่ม [สแกนต่อ] (ปิดแถบ) [จบรอบ] · แถบหายเองเมื่อสแกนคนแรก · ไม่ถามก่อนเข้า เพราะครูส่วนใหญ่ต้องการสแกนต่อทันที (ตัวเลข x/y มาจากเซิร์ฟเวอร์/ข้อมูลงาน → `ใช้ข้อมูลเดิม`)

**พฤติกรรมตามอุปกรณ์**

| อุปกรณ์ | เลย์เอาต์ตั้งรอบ |
|---|---|
| iPad นอน / คอม | ซ้าย: การ์ดงาน 2 คอลัมน์ + ขั้น 2–3 · ขวา sticky: สรุปรอบ + ปุ่มเริ่ม (เห็นตลอด) · คอมจอเตี้ย: เห็นการ์ดงาน 4 ใบก่อนเลื่อน · Tab ตามลำดับ 1→2→3→เริ่ม · Enter ที่กลุ่มเลือก = เริ่ม |
| iPad ตั้ง | คอลัมน์เดียว: ขั้น 1 (การ์ด 2 คอลัมน์) → 2 → 3 (3 การ์ดแถวเดียว) · แถบเริ่มติดล่างเต็มกว้าง |
| มือถือ | การ์ดงาน 1 คอลัมน์ · แถบเริ่มติดล่างเหนือแถบเมนู ปุ่มเต็มกว้าง ≥ 56px (นิ้วโป้งมือเดียวถึง) · เลือกงานแล้วเลื่อนไปขั้น 2 เบาๆ (ไม่ย้าย focus) |

## ช่วงที่ 2: กำลังสแกน (หน้าจอ B)

**ลำดับข้อมูล (ลำดับ DOM = ลำดับ focus):** แถบบน → (แถบแจ้ง: ต่อรอบเดิม / งานปิด / ไม่ทราบข้อมูล / ย้อนหลัง / ซ่อนชื่อ) → **hero** → **ช่องรับเลข + ปุ่มกล้อง** → แผงหลัก [การ์ดผล หรือ แป้นคะแนน (โหมดกรอก) → คำถาม (ยกเว้น/เลือกคน) → ส่งไม่สำเร็จ → ตารางเลขที่] → แผงข้าง [สแกนล่าสุด → ยังไม่ส่ง → คิวรอส่ง]

| บล็อก | เนื้อหา | กดได้ |
|---|---|---|
| hero | ชื่องาน (ตัดได้ 2 บรรทัด + `title`) · ห้อง ▾ (เปลี่ยนห้องของงานเดียวกัน → เริ่มรอบใหม่ห้องนั้น) · **รับแล้ว x จาก y คน** · วงแหวน % (= ส่งแล้ว ÷ (ห้อง − ยกเว้น) สูตรเดียวกับหน้าหลัก) · pill: วิธีให้คะแนน ▾ (ใช้กับครั้งถัดไป, D40) · วันที่รับ ▾ (ย้อนหลัง = แถบเตือนไอคอน alert-triangle + "กำลังรับงานย้อนหลัง · 30 ต.ค." + ปุ่ม "กลับเป็นวันนี้") · ชิป ออนไลน์/ออฟไลน์ + "รอส่ง n" · ป้ายเครื่องยิง ("เครื่องยิงพร้อม" / "คลิกหน้านี้ก่อนยิง") | pill ทุกอันเป็นปุ่ม (ขอบ + ลูกศร ▾) · วงแหวน = `role=img` |
| ช่องรับเลข | ขนาดใหญ่ สูง ≥ 56px · placeholder "ยิง QR หรือพิมพ์เลขที่ แล้วกด Enter" · `aria-label="รหัสนักเรียน"` | พิมพ์เลขที่ + Enter · ปุ่มกล้อง (`aria-pressed`) ≥ 56px |
| การ์ดผลล่าสุด (ใหญ่) | ไอคอน 40px + ชื่อ (≥ 28px) + บรรทัดรอง + คะแนน (ถ้ามี) + ปุ่ม **เลิกทำ** · ว่าง = "พร้อมสแกน" | เลิกทำ (D16) |
| แป้นคะแนน (โหมดกรอก) | แทนการ์ดผล: ชื่อ + เลขที่ + ชิป ทันกำหนด/ส่งช้า + ช่องคะแนน `x / เต็ม` + ปุ่มลัดคะแนน (เต็ม, เต็ม-1, เต็ม-2, ครึ่ง, "ล่าสุด n") + แป้นตัวเลข 3×4 + บันทึก | Enter บันทึก · "ให้คะแนนทีหลัง" |

**ปัญหากล้อง (`CameraProblem` 7 แบบ — แถบ `role=alert` ใต้ช่องรับเลข, ปุ่ม [ปิด]; ทุกแบบบอกว่า "เครื่องยิง/พิมพ์เลขที่ใช้ได้ตามปกติ"):**

ใช้ข้อความเดิมของ `EXPLAIN` (หัว + คำแนะนำ): `permission` ยังไม่ได้รับอนุญาตให้ใช้กล้อง · `no_camera` ไม่พบกล้องในเครื่องนี้ · `insecure` เปิดกล้องไม่ได้ — หน้านี้ไม่ได้เปิดผ่าน HTTPS · `unsupported` เบราว์เซอร์นี้ไม่รองรับการเปิดกล้อง · `busy` กล้องถูกใช้อยู่โดยแอปอื่น · `reader` ตัวอ่าน QR โหลดไม่สำเร็จ · `unknown` เปิดกล้องไม่สำเร็จ

กล้องเปิดอยู่: กรอบเล็ง + ปุ่ม ไฟฉาย (ถ้ามี) · สลับกล้อง · ยิงติดแล้ว: การ์ดผลเปลี่ยน + เสียง/สั่น (บน iPad ไม่รองรับสั่น — เสียงและการ์ดต้องพอ)

## ช่วงที่ 3: สรุปรอบ (หน้าจอ C)

**ลำดับข้อมูล:** หัว "จบรอบสแกน" + ชื่องาน → **hero สรุป** (วงแหวน 120px "ส่งแล้ว" + "ป.6/1 · เต็ม 20 · ไม่นับยกเว้น 2 คน" + ตัวเลข ส่งแล้ว / ยังไม่ส่ง **+ ส่งช้า n** (`ใช้ข้อมูลเดิม` นับจาก `late`)) → แบนเนอร์ "รอส่งขึ้นระบบ n คน — จะส่งเองเมื่อมีเน็ต อย่าเพิ่งปิดงาน" (ถ้ามี) → กลุ่ม: ส่งแล้ว n · ยังไม่มีคะแนน n [ให้คะแนนตอนนี้] · ยังไม่ส่ง n [คัดลอกรายชื่อ] · ยกเว้น n / รอส่ง n → **แถบการกระทำติดล่าง**

| การกระทำ | พฤติกรรม |
|---|---|
| ปิดรับงาน | แสดงเมื่องานยัง open · **ปิดใช้เมื่อออฟไลน์ หรือมีรอส่งขึ้นระบบ** พร้อมเหตุผลข้างปุ่ม ("ต้องออนไลน์ถึงปิดรับงานได้" / "รอรายการค้างส่งขึ้นระบบก่อน") · กด → ยืนยัน "ปิดรับ “<งาน>” ทุกห้อง?" บอกจำนวนยังไม่ส่งของห้องนี้ · [ปิดรับงาน] [ยังไม่ปิด] · สำเร็จ "ปิดรับงานแล้ว · ทุกห้อง" (D37) |
| คัดลอกรายชื่อ | ข้อความ: `รายชื่อยังไม่ส่ง "<งาน>" <ห้อง>` + "เลขที่. ชื่อ" ทีละบรรทัด · ปุ่มเปลี่ยนเป็น "คัดลอกแล้ว" 2 วิ (`aria-live`) · ซ่อนชื่อ = ปิดปุ่ม |
| ให้คะแนนตอนนี้ | → `/gradebook?class&asg&rows=awaiting` |
| กลับไปสแกนต่อ | เริ่มรอบใหม่งาน/ห้อง/โหมดเดิม |
| เลือกงานอื่น | กลับหน้า A |
| ไปสมุดคะแนน (primary) | → `/gradebook?class&asg` |
| **สแกนห้องถัดไป** (ข้อเสนอ P3) | ปุ่มรอง "ป.6/2 · ส่งแล้ว 0/30" เมื่องานนี้มีหลายห้อง → เริ่มรอบห้องนั้น |

ชื่อใน 3 กลุ่ม = ชิป "เลขที่ ชื่อสั้น" สูงสุด 18 + "และอีก n คน" · สีกลุ่ม + **ไอคอน + คำหัวกลุ่ม** (check/pencil/circle-dashed ขอบเส้นประ) · ยังไม่ส่ง n = 0 → "ทุกคนส่งครบแล้ว" (ไอคอน check ใหญ่ — ฉลองเล็กน้อยสไตล์ธีม) · `role=status` ประกาศ "จบรอบ: ส่งแล้ว 26 จาก 31 คน"

พฤติกรรมอุปกรณ์: นอน/คอม = hero ซ้าย + กลุ่มรายชื่อขวา, แถบการกระทำติดล่าง · ตั้ง = คอลัมน์เดียว · มือถือ = "ไปสมุดคะแนน" เต็มกว้าง ปุ่มอื่นแถวรอง ≥ 44px, "ปิดรับงาน" แยกบรรทัดกันกดพลาด

## การเข้าถึง (accessibility) ♿

**ลำดับ focus** (ตาม DOM ไม่ใช้ `order` CSS): ข้ามไปเนื้อหา → เมนู → แถบบน → แถบแจ้ง → hero (ห้อง · วิธี · วันที่รับ) → **ช่องรับเลข** → ปุ่มกล้อง → การ์ดผล (เลิกทำ)/แป้นคะแนน/การ์ดถาม → ส่งไม่สำเร็จ → ตารางเลขที่ (ลูกศรย้ายช่อง, Tab เข้า/ออกครั้งเดียว, Enter/Space = แตะ) → แผงข้าง
- **focus หลังกด:** หลังปิดแผ่น/เลือกในเมนู/เลิกทำ/ตอบคำถาม → คืน focus ที่ช่องรับเลขบนอุปกรณ์ที่มีคีย์บอร์ด (`focusScan` เดิม) · จอสัมผัสล้วน **ไม่ดึง** focus (แป้นพิมพ์จะเด้ง) — HID ยังรับได้เพราะฟังทั้งหน้า และป้าย "เครื่องยิงพร้อม" บอกสถานะ · แป้นคะแนนเปิดขึ้น → focus ที่ช่องคะแนน
- แผ่น/ลิ้นชัก: ย้าย focus เข้าข้างใน · วน focus · Esc ปิด · คืน focus ปุ่มที่เปิด
**aria-live:** การ์ดผล = `role=status` (polite) ประกาศ 1 ครั้งต่อผล (ไม่ประกาศซ้ำเมื่อ re-render) · ผลที่ต้องตัดสินใจ/ผิดพลาดร้ายแรง = `role=alert` · เลิกทำ: ประกาศ "เลิกทำได้ 5 วินาที" ครั้งเดียว ไม่อ่านตัวนับทุกวินาที · ตัวเลข "รับแล้ว x จาก y" อัปเดต `aria-live=off` (ไม่ท่วม)

**เวลาจำกัดของเลิกทำ (WCAG 2.2.1):** 5 วินาทีตาม D16 — แก้ภายหลังได้เสมอ (แตะช่อง → ยกเลิกการส่ง/สแกนซ้ำ) · ปุ่ม "เลิกทำ" ในการ์ดผลค้างจนมีสแกนถัดไป · หยุดตัวนับเมื่อ hover/focus (เสนอ)

**contrast/สี:** ทุกคู่ข้อความ/พื้นในการ์ดผล 5 โทน (success/warning/danger/accent/idle) ≥ 4.5:1 ทั้ง 3 ธีม × สว่าง/มืด (Web Designer ตรวจซ้ำทุกคู่ รวมโหมดมืดของ warm/playful ที่ยังไม่คำนวณ) · เส้นขอบควบคุม `--border-control` ≥ 3:1 · ไอคอนสถานะบนพื้นสีเข้ม ≥ 3:1 · ไม่สื่อด้วยสีอย่างเดียว: 5 สถานะ = ไอคอน+คำ+รูปขอบ (ทึบ/เส้นประ) · ผลสแกน = ไอคอน+คำ+เสียง/สั่น · ซ่อนชื่อ/ฉายจอ = ไอคอน+คำ

**reduced-motion:** `prefers-reduced-motion: reduce` → ปิดแอนิเมชันเติมวงแหวน, การ์ดเด้ง, หมุน spinner (แสดงไอคอนนิ่ง + คำ "กำลังโหลด") · motion ปกติ: การ์ดผลเปลี่ยนโทน fade ≤ 150ms · วงแหวนเติม ≤ 300ms · ห้ามกะพริบ > 3 ครั้ง/วินาที (ผลผิดห้ามแฟลชทั้งจอ) · ความหมายครบแม้ไม่มี motion/เสียง

**เป้ากด:** ช่องรับเลข/ปุ่มกล้อง/เลิกทำ/เริ่มสแกน ≥ 56px · ช่องตาราง ≥ 44×44 ช่องห่าง ≥ 8px · ปุ่มคะแนนลัด/แป้นตัวเลข ≥ 56px (เดิมใหญ่ขึ้นตาม D29) · pill/ชิป ≥ 44px สูง · ตัวอักษรขั้นต่ำ 13px, ผลสแกน/ชื่อ ≥ 20px บน iPad

**label:** ปุ่มไอคอนล้วนทุกปุ่มมี `aria-label` (สแกนด้วยกล้อง · ไฟฉาย · สลับกล้อง · "ตัวเลือก เลขที่ N <ชื่อ>" · ลบตัวเลขท้ายสุด · บันทึก) · ช่องคะแนน `aria-describedby` ชี้ข้อความผิดพลาด `aria-invalid` · วงแหวน `role=img` + ตัวเลขใน label ("ส่งแล้ว 26 จาก 31 คน ร้อยละ 84")
