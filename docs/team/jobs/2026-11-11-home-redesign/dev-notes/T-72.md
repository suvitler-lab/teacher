## epoch ของ Random.tsx — สรุป: epoch ซ้ำซ้อนกับ clearTimers โดยโครงสร้าง พิสูจน์เดี่ยว ๆ ไม่ได้ แต่ "คู่" ถูกพิสูจน์แล้ว
- ทุกจุดที่ `epoch.current++` (เปลี่ยนห้อง, เปลี่ยนโหมด, unmount) มี `clearTimers()` คู่กันเสมอ และค่า epoch ถูกอ่านเฉพาะใน callback ของ `later()` (step / finish / ข้าม 700ms) หรือ `finish` ที่ถูกเรียกจาก step ซึ่งก็อยู่ใน timer · timer ที่ถูกยกเลิกไม่ทำงาน → ไม่มีทางที่ callback ของ epoch เก่าได้รันโดยที่ clearTimers ไม่ยกเลิก (JS เธรดเดียว ไม่มีจุดแทรกกลาง callback)
- สถานการณ์ที่ PM เสนอ (ผลโหลดประวัติ/เช็คชื่อของห้อง A ตอบช้าหลังไป B) **ไม่ใช่งานของ epoch** แต่เป็นของ `histEpoch` (ประวัติ) และ `useLoadGuard` (เช็คชื่อ) — ช่องว่างจริงที่ไม่มีเทสต์ → เขียนเทสต์ด้วย promise deferred (6 ข้อ):
  - เช็คชื่อห้อง c1 ตอบช้าหลังไป c2 → ยังเป็นตัวเลขของ c2 (2 คน ไม่ใช่ 3) และสุ่มแล้วบันทึกเฉพาะ id ของ c2 · c1 ล้มช้า → ไม่มี alert/ข้อความผิดพลาดทับ c2
  - ประวัติ c1 อ่านเสร็จช้าหลังไป c2 → c2 ยังเป็น "สุ่มแล้ว (1) ยังไม่ถูกสุ่ม (1)", สุ่มต่อได้คนที่เหลือ, key c2 เก็บ id c2 เท่านั้น · ระหว่างอ่านประวัติยังเป็น "สุ่มแล้ว (–)" สุ่มไม่ได้
  - ข้าม (รอ 700ms) แล้วเปลี่ยนห้อง → ห้องใหม่ไม่ถูกสุ่ม ประวัติ c2 ว่าง · เปลี่ยนโหมดระหว่างหมุน (motion จริง) → ไม่มีผล ไม่บันทึก
- mutation: ถอดเช็ค `fresh()` (ตอบสำเร็จ) ล้ม · ถอด `if (fresh())` ที่ catch ล้ม · ถอดเช็ค `histEpoch` ล้ม (ทั้งสามข้อละ 1 เทสต์)
- ถอดเช็ค epoch ทั้ง 3 จุด (ชุด hr-random* + random-page 60 เทสต์) → **ไม่ล้ม** · ถอด clearTimers อย่างเดียว (ให้เหลือ epoch) → **ไม่ล้ม** (epoch กันได้เอง) · ถอด **ทั้งคู่** → **ล้ม 2 ข้อ** (เทสต์ข้าม+เปลี่ยนห้อง และเปลี่ยนโหมดระหว่างหมุน) = เทสต์ใหม่พิสูจน์ว่ากันได้จริงทั้งคู่ แต่แยกชั้นไม่ได้ เพราะแต่ละชั้นพอตัวเดียว (ชั้นสำรองซ้ำซ้อน ตามที่ T-44 R-4406 ระบุ)
