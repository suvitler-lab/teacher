### ควรแก้ (กลาง)

**R-3001 · เทสต์ contrast ไม่ได้ตรวจคู่ที่ใช้จริงส่วนใหญ่** — `test/unit/hr-sweep-colors.test.ts:104-122`
- `pairs()` นับเฉพาะกฎที่ประกาศ `color` และ `background` เป็น `var(--x)` เปล่า **ในกฎเดียวกัน** (บรรทัด 119 `if (!fg || !bg) continue`) — ตัวหนังสือสถานะที่อยู่ในลูก เช่น `.fb.success .name { color: var(--text-success) }` บนพื้นของแม่ `.fb.success { background: var(--bg-success) }` (scan.css:181-182) หรือ `.fb .ic { color: var(--surface-2) }` + `.fb.idle .ic { background: var(--text-muted) }` (scan.css:176,195) ไม่ถูกตรวจเลย · ค่าที่เป็น `color-mix(...)`/`var(--a, b)` ถูกข้ามเงียบ (บรรทัด 102)
- สถานการณ์ที่พัง: T-29 ปรับ `--text-success` หรือ `--bg-success` ของชุดใดชุดหนึ่งจนตัวหนังสือผลสแกน < 4.5:1 → เทสต์ hr-sweep ยังเขียว · พิสูจน์แล้วด้วย R-3002 ซึ่งตอนนี้ไม่ผ่านจริงแต่เทสต์ไม่จับ
- แนวทางแก้: เพิ่มตารางคู่ข้ามกฎที่ระบุชัด (selector ลูก → token พื้นของแม่ หรือ `--surface-2` เมื่ออยู่ใน `.card`) สำหรับ `.fb.*`, `.ob-done`, ป้ายสถานะ att/grade อย่างน้อย; หรือกำหนดให้กฎที่มี `color: var(--x)` แต่ไม่มีพื้นในกฎเดียวกัน ถูกตรวจกับ `--surface-2` และ `--surface-1` โดยปริยาย

**R-3002 · ไอคอนสำเร็จหน้าเริ่มต้นใช้งาน contrast ต่ำกว่า 3:1 ในธีมสดใสโหมดสว่าง** — `src/styles/onboarding.css:24`
- `.ob-done { color: var(--fill-success) }` อยู่ใน `.ob-card.card` (Onboarding.tsx:149,257; `.card` พื้น `--surface-2` base.css:103) → playful light `#22c58b` บน `#ffffff` = **2.23:1** (< 3:1 ไอคอน AC-37/BR-10) · ชุดอื่น 3.18–6.86 ผ่าน
- เป็นค่าที่มีมาก่อน (diff แค่ตัด fallback) แต่ T-30 รับขอบเขต "ให้ผ่าน contrast 6 ชุด" ของไฟล์นี้
- แนวทางแก้: ใช้ `--text-success` (ออกแบบไว้ ≥ 4.5 บนพื้นอ่อน) แทน `--fill-success` แล้วคำนวณยืนยันทั้ง 6 ชุด

### เสนอ (ต่ำ)

**R-3003 · ช่องโหว่ของตัวตรวจสีตายตัว** — `test/unit/hr-sweep-colors.test.ts:40`, `:16`, `:18`

**R-3004 · ตัด fallback ของ `.hbar`** — `src/styles/grade.css:48`
