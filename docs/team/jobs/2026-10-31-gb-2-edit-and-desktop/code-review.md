## ตรวจแล้วไม่พบปัญหา

1. **แตะ "รวม" ไม่บันทึกค่าโดยไม่ตั้งใจ**: ช่องกรอกที่เปิดใหม่เริ่มจาก `initial` = คะแนนเดิม ถ้า blur โดยไม่พิมพ์อะไร `commitScore` → `decideCellCommit` จะได้ `noop` (`Gradebook.tsx:210-211`) จึงไม่มีการเขียน ถ้ามีช่องอื่นกำลังแก้อยู่แล้วไปแตะช่อง "รวม" ช่องเดิมจะ blur และ commit ค่าที่พิมพ์ไว้ ซึ่งเหมือนกับการแตะช่องคะแนนอื่นอยู่แล้ว (พฤติกรรมเดิม ไม่ใช่ regression) ลำดับโฟกัส: ช่อง "รวม" ที่ถือโฟกัสถูก unmount ตอนกลุ่มกาง จากนั้น effect `[foldTaps]` (`:418-424`) เรียก `setEditing` แล้ว `CellInput` โฟกัสตัวเองตอน mount (`:729`) ไม่มีอะไรมาแย่งโฟกัส `scrollToAsg`/`scrollIntoView` ไม่ทำให้ blur ส่วน Enter/Space มีเงื่อนไข `e.target === e.currentTarget` + preventDefault และ keyup ที่ตกไปที่ input ไม่มี handler จึงไม่ commit ซ้ำ
2. **งานแรกถูกซ่อนด้วยเมนูคอลัมน์**: `cols` มาจาก `displayGroups` ซึ่งเป็นงานที่แสดงอยู่ (`gbColumns.ts:68-70`) กลุ่มที่ไม่มีคอลัมน์แสดงถูกตัดออก ดังนั้น `cols[0]` คืองานแรก "ที่แสดง" เสมอ และ `firstId` ไม่เป็น undefined ในทางปฏิบัติ (กรณีนั้นยังมี fallback เป็น `toggleGroup`) กรณีหลายงานใช้งานแรกตาม brief เทสต์ครอบคลุมทั้งคลิก (k2/w1) และ Enter/Space
3. **localStorage v2**: `loadGroupMode` อ่านเฉพาะคีย์ใหม่ ตรวจค่าด้วย whitelist และหุ้ม try/catch (`gbGroups.ts:22-28`) ค่าเก่า ค่าขยะ หรือ storage ที่ throw จะได้ `"none"` ไม่ crash มีเทสต์ครอบ (`gradebook-groups.test.ts:40-46, 69-80`) ส่วนสถานะพับเก็บในหน่วยความจำเท่านั้น (`foldTaps`) จึงไม่มีค่า "พับอัตโนมัติ" ค้างให้ต้องล้าง
4. **CSS**: `base.css:7` มี `* { box-sizing: border-box }` อยู่แล้ว การใส่ `box-sizing` ซ้ำที่ name-col จึงไม่เปลี่ยนอะไร ค่า clamp ใหม่ (10.7–15.2rem) ≥ ค่าเดิม (9.5–14rem) ทุกความกว้าง บน iPad ชื่อจึงได้พื้นที่เท่าเดิมหรือมากกว่า ไม่ตัดชื่อไทยยาวมากขึ้น (แลกกับพื้นที่คอลัมน์งานบน iPad แนวตั้งที่ลดไป ~1.2rem ซึ่ง AC-04 วัดแล้ว) การเอา `min-width:100%` ออกทำให้ตารางชิดซ้าย ความกว้างเงาขอบ `::before left: var(--gb-name-w)` ยังตรงกัน หัวสะสม rowSpan: specificity ของ `tr.gh th` (z-index 4) ชนะ `thead .tot-col` (6) แต่ยังสูงกว่าหัวงาน (2) และ body tot-col (3) และอยู่หลังสุดใน DOM จึงทับหัวกลุ่มที่เลื่อนผ่านได้ถูกต้อง ใช้ `top:0` ส่วนแถว hd ใช้ `top: var(--gb-gh)` ไม่ซ้อนกัน

#### R-09 · จอคอม: `.gb-nav` ห้ามขึ้นบรรทัดใหม่ (`nowrap`) เมื่อมีปุ่มกระโดดหลายประเภท อาจล้นออกนอกหน้าในแนวนอน
- `src/styles/grade.css:147` (`.gb-bar2 .gb-nav { flex: 1 1 22rem; flex-wrap: nowrap; }`)
- สถานการณ์: `.gb-nav` เป็น flex item ที่ไม่ได้ตั้ง `min-width:0` ความกว้างต่ำสุดจึงเท่ากับเนื้อหา คือ "เลื่อนดู" + minimap (อย่างน้อย 9rem) + ปุ่มประเภททุกปุ่ม (`white-space:nowrap`) ที่หน้าต่างกว้าง 1100–1280px เมื่อหักแถบข้างแล้วเหลือพื้นที่เนื้อหาราว 800–1000px ถ้าครูมีงาน 6–8 ประเภท และตั้งตัวอักษร 18px ขึ้นไป ปุ่มกระโดดอาจกว้างกว่าพื้นที่ที่เหลือ แถบจะล้นไปทางขวาจนหน้าเลื่อนแนวนอนได้ (ขัด AC-03 "ไม่เลื่อนแนวนอนทั้งหน้า") ก่อนรอบ 2 แถบนี้ขึ้นบรรทัดใหม่ได้ ความมั่นใจ: กลาง เพราะ dev-notes ไม่ได้บอกว่า fixture 19 งานมีกี่ประเภท
- แนวทาง: คง `flex-wrap: wrap` ไว้ หรือใส่ `min-width:0` ให้ `.gb-nav` คู่กับ `overflow-x:auto` ที่กลุ่มปุ่ม แล้วให้ QA ลองกรณีงาน 6–8 ประเภท ที่ 1100px ตัวอักษร 18px
