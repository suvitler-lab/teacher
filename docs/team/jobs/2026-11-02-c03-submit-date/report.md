## ผลตาม AC (ฝั่งเซิร์ฟเวอร์)
- รับ `receivedDate` (ค.ศ.) ใน op ที่ทำให้ช่องเป็นส่งแล้วครั้งแรก ทุกวิธี (กล้อง/เครื่องยิง/พิมพ์/ตาราง) → เก็บใน `submitted_at` (12:00 น. ไทยของวัน ไม่เกินตอนนี้; วันเดียวกับ eventAt = เวลาจริง) · `late` ยังคำนวณจากกติกาเดิม (BR-04)
- แก้วันที่ช่องที่ส่งแล้ว: op `grid` + `dateOnly` (คะแนนไม่ถูกแตะ, ประวัติ before/after, ทำได้แม้งานปิดรับ, ย้อนกลับด้วย op แก้วันที่อีกตัว)
- ทั้งห้อง `all-submitted` รับ `receivedDate` · ย้อนกลับทั้งกลุ่มคืน `submitted_at` ตรงถึงมิลลิวินาที · action อื่นที่ส่งวันที่ = 400
- เหตุผลปฏิเสธใหม่ 5 ค่า (วันที่ผิดรูป/อนาคต/ก่อนวันมอบหมาย, ช่องยังไม่ส่ง, op ไม่อนุญาต) · ปฏิเสธรายการเดียวไม่ทำให้อีก 49 รายการใน batch ล้ม
- ไม่มีเพดานย้อนหลัง (Q2) แต่กันปีก่อน 2000 (`MIN_RECEIVED_DATE`) — Reviewer/QA พบว่าปีพิมพ์ผิด (เช่น 1926) ทำให้ `submitted_at` ติดลบ และไฟล์สำรองกู้คืนไม่ได้ (R-01/B-01) แก้แล้วพร้อมเทสต์
- แอปเก่าที่ไม่ส่งฟิลด์ใหม่: พฤติกรรมเหมือนเดิมทุกไบต์ · ต้นทุนฐานข้อมูลของ bulk/batch เท่าเดิม (AC-24)
- 💰: เปลี่ยนเฉพาะจำนวน "ช้า" (ตัวอย่าง 20→5) คะแนนรวม/ค้างส่งไม่เปลี่ยน
- ตรวจ: typecheck ผ่าน · 104 ไฟล์ / 1279 เทสต์ผ่าน · QA ทดสอบ HTTP จริง (ส่งซ้ำ, แข่งกันสองเครื่อง, เที่ยงคืนไทย, ทั้งห้อง+ย้อนกลับ) ผ่าน · Reviewer (opus) ผ่านหลังแก้ R-01
