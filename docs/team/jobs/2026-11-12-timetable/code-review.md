## ควรแก้ (P2 — กลาง)

### R-01 โครงค่าเริ่มต้นจาก `period_times` เดิมผิดกติกาของตัวเองได้ และทิ้งคาบ 8 — data/bug · `shared/timetable.ts:211-218` (+ `:73`)

- ปัญหา: `resolveFrame` (ไม่เคยตั้งโครง) ใช้เวลาเริ่มจาก `period_times` แล้วตั้ง "จบ = เริ่ม + 60" ตายตัว และมีแค่ 7 คาบเสมอ ไม่ตรวจซ้ำว่าผลผ่าน `validateFrame`
- สถานการณ์ที่พัง (รันจริงในโพรบ): `period_times` คาบละ 50 นาที `{"1":"08:30","2":"09:20","3":"10:10","4":"11:00","5":"13:00","6":"13:50","7":"14:40","8":"15:30"}` (ฟีเจอร์เดิม BR-57 ครูตั้งไว้ได้) → คาบ 1 08:30–09:30 ทับคาบ 2 09:20–10:20 … คาบ 4 11:00–12:00 ทับพักกลางวัน · `validateFrame` คืน 6 จุด (`period_order` ×5, `break_overlaps_period`)
  - ผล: ก่อนครูกดบันทึกโครง หน้าหลักเวลา 09:25 มีสองคาบเป็น "ตอนนี้" (`logic.ts:157` เลือกคาบแรก) → ปุ่มทางลัด "เช็คชื่อ <ห้องคาบ 1>" ทั้งที่ครูสอนคาบ 2 แล้ว · แถบแสดงสองช่อง "ตอนนี้"
  - คาบ 8 ใน `period_times` เดิมหายจากโครง → พอครูกดบันทึกโครง (EP-12 เขียน `period_times` = 7 คาบ) เกณฑ์สายคาบ 8 ของหน้าเช็คชื่อหายไปเงียบ ๆ (`Attendance.tsx:69` คาบที่ไม่มีเวลา = ไม่ตัดสินสาย)
  - คาบที่ครูเคยเว้นว่าง ("เว้นว่างได้ถ้าไม่ใช้คาบนั้น") จะได้เวลาเริ่มทุกคาบหลังบันทึกโครงครั้งแรก → เริ่มตัดสินสายในคาบที่เคยไม่ใช้
- แนวทางแก้ (ต้องให้ Tech Lead ตัดสิน เพราะสัญญา part-5 บรรทัด `resolveFrame` เขียนสูตร +60 ไว้): จำนวนคาบ = max(7, คีย์สูงสุดใน `period_times` ≤ 8) · จบ = min(เริ่ม + 60, เวลาเริ่มคาบถัดไป) · ถ้าพักกลางวันทับ ให้เลื่อน/ตัดพัก · ถ้าผลยังไม่ผ่าน `validateFrame` ให้แอปถือว่า "ยังไม่มีคาบตอนนี้" (ไม่ใช้คำนวณตอนนี้/ทางลัด) จนครูบันทึกโครง · เพิ่มเทสต์ legacy 50 นาที + คีย์ "8"
- สถานะ: เปิด

### R-02 [ลองอีกครั้ง] หลังหมดเวลาทับการแก้ของเครื่องอื่นโดยไม่มี 409 — data (🔄) · `src/lib/timetable/store.ts:185-186` + `:328-334`

- ปัญหา: กรณี `timeout` เก็บ `lastFailed.slots` (รายการทั้งภาคที่คิดจากรุ่นเดิม) แล้ว `loadTerm(force)` ซึ่งรับรุ่นล่าสุดของ server · `retryLast` ส่งรายการเก่านั้นด้วย `baseRev` = รุ่นใหม่ที่เพิ่งโหลด → server ไม่มีทางรู้ว่ารายการคิดจากรุ่นเก่า
- สถานการณ์ที่พัง: iPad บันทึกเพิ่ม พฤ คาบ 7 (rev 7→8) · คอมยังเห็น rev 7 แก้ จ คาบ 2 → PUT ช้าเกิน 15 วินาที (หมดเวลา) → คอมโหลด rev 8 (มีคาบของ iPad) → ครูกด [ลองอีกครั้ง] → PUT รายการที่ไม่มี พฤ คาบ 7 + `baseRev 8` → 200 · คาบที่ iPad เพิ่มหายเงียบ (ขัด BR-09/AC-41 "ไม่ทับเงียบ") · ถ้าคำขอแรกบันทึกไปแล้วแล้วเครื่องอื่นแก้ต่อก่อนกดลองใหม่ ผลเหมือนกัน

- สถานะ: เปิด

### R-03 bootstrap อ่าน `timetable_rev` กับคาบคนละคำสั่งขนานกัน (ไม่แน่ใจลำดับของ D1) — data (🔄) · `worker/routes/bootstrap.ts:14-35, 56, 72`

- สถานะ: เปิด

## จุดที่ตรวจแล้วไม่พบปัญหา

- **baseRev/409 (EP-11):** ตรวจ rev ก่อน (`timetable.ts:81`) และซ้ำใน batch พร้อมปีที่แก้ได้ (`:107`) · `abortIf` โครงเทียบค่าดิบ (`:109`) · ห้อง/วิชาของคาบใหม่หรือเปลี่ยนที่เพิ่งเก็บ (`:111-115`) · catch หาเหตุตามลำดับสัญญา (read_only → timetable_changed → frame_changed → bad_timetable → 500) · `changed:false` ไม่เพิ่มรุ่น ไม่มีประวัติ · ลำดับข้อ 1–7 ตรงตาราง
- **EP-12:** UPDATE rev ก่อน DELETE (ภาคที่มีคาบถูกลบเท่านั้น) · `period_times` เขียนในชุดเดียว · ภาคปีเก่าไม่ถูกแตะ (`OUTSIDE` จำกัด `year = ?1`) · ไม่มีภาค → `year null` ทำงานถูก · `period_frame_owned` ใน `catalog.ts` ใส่ `abortIf` หน้าแรกของ batch และหาเหตุหลังล้ม · ฟอร์มตั้งค่าไม่ส่ง `period_times` แล้ว (`Settings.tsx:39, 151`)
- **restore/backup/reset:** `timetable_slots` ท้าย `BACKUP_TABLES` ทั้ง server/แอป/RestoreModal · ลบย้อนลำดับ (ลูกก่อน) · ไฟล์ v6 ไม่มี counts ของตารางนี้ → ผ่าน `missing` และ guard ใน batch (วนตาม counts ของไฟล์) · settings ถูกแทนทั้งตาราง → v6 ได้โครงค่าเริ่มต้นจาก `period_times` ในไฟล์ · กติกา `kind_fields`/`wrong_school_year`/`duplicate_slot`/FK อยู่ใน guard เดิม · `dataFingerprint` มีตารางนี้ · reset ลบก่อน terms/classes/subjects · ไม่พบการลบถาวรของ classes/terms/subjects ที่อื่นใน `worker/`
- **เวลา Asia/Bangkok:** `clock.ts` ใช้ UTC+7 คำนวณเอง ไม่พึ่ง zone เครื่อง · ช่วงครึ่งเปิด `[start, end)` · ข้ามวันด้วยปฏิทินจริง (`addDays`) · หยุดที่วันสิ้นสุดภาค · `?now=` ใช้ได้เฉพาะ dev/localhost/.test
- **ทางลัด BR-15:** `logic.ts:122-139` — คาบสอนห้องที่กำลังสอน → คาบสอนห้องถัดไปของ **วันนี้** → ไม่มีปุ่ม · ข้ามกิจกรรม/ห้องหรือวิชาที่เก็บ/ห้องที่แอปไม่รู้จัก · วันไม่ใช่วันเรียน = ไม่มีปุ่ม · ภาคจบแล้ว = ไม่มีแถบ · ตรงตัวอย่าง BR-15 ทุกข้อ (ยกเว้นกรณีโครงซ้อนจาก R-01)
- **ต่อภาค:** หน้าหลักใช้ภาคปัจจุบันเสมอ (`ttToday`) · แคช bootstrap แทนเฉพาะภาคปัจจุบัน + epoch เดิม · ปีเก่า readOnly ทั้ง server และแอป · Timeline/แถบซ่อนเมื่อดูปีเก่า (`a/index.tsx:60-62`, `Home.tsx:77`) · คัดลอกข้ามปีจับคู่ชื่อห้องที่ตัดช่องว่างกับห้องที่ใช้งานของปีปลายทาง
- **ออฟไลน์อ่านอย่างเดียว:** `commitSlots`/`saveFrame`/`prepareCopy` ปฏิเสธเมื่อ `online === false` ไม่เข้าคิว · ปุ่มบันทึกโครงปิด + ข้อความ · อ่าน/พิมพ์จากแคชพร้อม "ข้อมูลเมื่อ HH:MM" · ออกจากระบบล้างตาราง (`ttResetAll`)
- **XSS/ข้อความอิสระ:** ชื่อกิจกรรม ชื่อพัก ชื่อครู/โรงเรียนแสดงเป็น text/attribute ของ Preact ทั้งหมด (escape อัตโนมัติ) · ข้อความ error ของ server ที่มีชื่อพักเป็น JSON และแสดงเป็น text · ความยาว 40 ตรวจทั้ง zod/`slotIssues` (UTF-16 เข้มกว่า SQLite `length`) และ CHECK ใน DB
- **performance:** ทุกคำสั่งมีขอบเขต (≤ 56 แถว/ภาค · counts GROUP BY) · ไม่มี query ใน loop · EP-11 เขียน 7 คำสั่ง + guard · EP-12 8 คำสั่ง (< 50) · `ttToday` คำนวณ ≤ 56 คาบต่อนาที
- **a11y ของส่วนใหม่:** แถบมี `aria-label` ต่อช่อง + `aria-current="time"` + live region แบบ polite ที่ข้อความเปลี่ยนเฉพาะเมื่อสถานะเปลี่ยน · ฟอร์มโครงเวลา: ทุกช่องมีชื่อ, `aria-invalid` + `aria-describedby` ชี้ข้อความผิด, spinbutton ใช้ลูกศรได้, ปุ่มวัน `aria-pressed`, โฟกัสไปช่องผิดช่องแรก · กล่องยืนยันเป็น `alertdialog` โฟกัสเริ่มที่ "ยกเลิก" · การ์ดตายตัวใน "ปรับหน้าหลัก" มีแค่สวิตช์ · ปุ่ม ≥ `--tap`
