|---|---|---|
| D01 | ผู้ใช้เลือก | ผู้ใช้จริงเป็นครูหนึ่งคนหลายเครื่อง |
| D02 | ผู้ใช้เลือก | ทดลองหนึ่งห้องก่อนเปิดใช้วงกว้าง |
| D03 | ผู้ใช้ระบุ | ต้องรองรับ iPad คอมพิวเตอร์ และมือถือ |

| D05 | ข้อเสนอในแผน | ใช้สถาปัตยกรรมและ design system เดิม; ความถูกต้องของข้อมูลและการกู้คืนมาก่อนการตกแต่ง |
| D06 | ค่าเริ่มต้นของแผนทดลอง | บล็อกการย้ายเด็กที่มีประวัติไปห้องอื่น และการนำเข้าเด็กเดิมข้ามปี จนมีโมเดล enrollment; reimport ห้องเดิมยังได้ ไม่เปลี่ยนรหัสเด็กเพื่อหลบ guard |
| D07 | ค่าเริ่มต้นของแผน | ใช้ transactional guards เดิมเพื่อป้องกัน setup/term ซ้ำก่อน; ไม่ลบหรือรวมข้อมูลซ้ำอัตโนมัติ ไม่บังคับ migration ใหม่ในรอบ hardening |
| D08 | ค่าเริ่มต้นของแผน | ให้ timeout ทุก network path พร้อมความหมายว่า write อาจสำเร็จแล้ว; retry เฉพาะ operation ที่ idempotent และรักษา opId เดิม |

24 ต.ค. 2569 — D11 (ผู้ใช้ชี้แจง): ครูส่วนใหญ่สอนเฉพาะ ป.6 เมื่อเด็กเลื่อนชั้นแล้วไม่ได้สอนต่อ รูปแบบหลักจึงเป็นนักเรียนคนละรุ่นในแต่ละปี: เก็บห้อง/นักเรียน/คะแนน/เช็คชื่อปีเก่าไว้ เปิดห้อง ป.6 ว่างสำหรับปีใหม่ แล้วนำเข้านักเรียนรุ่นใหม่ ไม่ต้องทำระบบเลื่อนชั้นเด็กหรือ enrollment หลายปีเป็นเงื่อนไขส่งมอบ หากอนาคตมีกรณีเด็กซ้ำชั้น ครูสอนต่อ หรือย้ายห้องพร้อมประวัติ จึงเปิดงานออกแบบรองรับเฉพาะกรณีนั้น โดยยังคง guard ป้องกันรายงานเดิมเปลี่ยนไว้
